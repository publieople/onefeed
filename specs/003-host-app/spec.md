# 宿主应用规格（003-host-app）

> 目标：把插件运行时（002）变成能给人看的东西——一条命令起服务，屏幕上就是一屏混合信息流。
> 起点 2026-11-14，交付 11-28 现场、11-29 决赛。上游文档：000 宪章、002 插件架构、003-delivery 计划。

## 1. 问题

插件层已经能拉到六个平台的真实数据，但入口是命令行。给别人看的时候，命令行输出的字段表没有说服力；评委要看的是「一屏刷完六个 App」这件事本身。

## 2. 用户与场景

单个用户（冯周杰本人）在自己电脑上、投屏给评委看。三个场景按重要性排序：

1. **演示**：双击/一条命令，10 秒内出现混合流，点开一条能看到正文与评论，切到原平台。
2. **日常**：早上打开看一轮，按平台过滤，把不想看的平台关掉。
3. **扩展**：从插件市场装一个新平台，不重启进程。

## 3. 范围

### 3.1 做

- 本地服务：FastAPI，只绑 {127.0.0.1}:8787，托管前端构建产物
- 信息流：六平台混排、按平台过滤、按时间/热度排序切换
- 卡片：video / images / article / short / list 五种形态
- 详情：右侧抽屉，正文、作者、统计、去原平台
- 插件市场：订阅 registry、安装、更新、禁用、卸载
- 登录：需登录平台的状态显示与扫码入口
- 刷新：手动刷新 + 采集进度可见
- 降级：单平台失败不影响整屏
- DEMO：零网络模式读 fixtures

### 3.2 不做

- 云端部署、Docker 镜像、公网域名
- 账号、多用户、权限
- 手机端 / 桌面端打包
- 点赞、评论、发布等写操作
- 推荐算法调参（先规则，后语义去重）
- 内置任何平台签名算法（宪章第 4 条）

## 4. 功能需求

### FR-1 单命令启动

- `python -m onefeed` 起服务并把浏览器打开到 127.0.0.1:8787
- `python -m onefeed --demo` 零网络启动
- `python -m onefeed --no-browser` 只起服务
- 端口被占用时报错说清是哪个进程占用，不静默换端口
- 启动到可用 < 5s（不含采集）

### FR-2 信息流读取

- 首屏读本地 SQLite 缓存，不触发网络；缓存为空时显示「正在采集」并自动触发一轮
- 分页：默认 30 条/页，滚动到底加载下一页，游标用 (published_at, id)
- 过滤：按平台、按 kind
- 排序：freshness（默认，按平台内发布时间分位）、engagement（平台内归一后的互动）
- 时间字段缺失的条目排在后面，不伪造时间

### FR-3 卡片呈现

五种 kind，缺字段按 §6 降级：

| kind | 形态 | 必须显示 |
|---|---|---|
| video | 16:9 封面 + 时长角标 | 标题（2 行截断）、作者、播放/点赞 |
| images | 1/2/3/4/9 宫格 + 标题 | 标题（3 行截断）、作者、点赞 |
| article | 左侧 4:3 缩略图 + 右侧标题摘要 | 标题、作者、阅读/点赞 |
| short | 纯文本卡 + 来源徽标 | 标题、作者、回复/点赞 |
| list | 一行标题 + 热度数值 | 标题、热度 |

平台色标：B 站 #00A1D6、小红书 #FF2442、抖音 #FE2C55、掘金 #1E80FF、V2EX #778087、知乎 #0084FF；插件自带 themeColor 时以插件为准。

### FR-4 详情

- 卡片点击 → 右侧抽屉滑出（宽 480px，1366 屏不遮住列表首列）
- 内容：大图/封面、标题、作者（头像 + 名字）、发布时间、统计、正文摘要、「去原平台」按钮
- 评论：能拿到的平台显示前 10 条（B 站楼中楼、抖音热评）；拿不到就显示「该平台未提供评论」，不显示空框
- 抽屉内刷新单条：只重拉这一条，不动列表

### FR-5 插件市场

- 市场页列出 registry 里的插件：名称、版本、能力（http/cli/browser）、kind、是否已安装、是否有更新
- 订阅地址可在设置里改，默认官方 registry
- 安装：下载 → 校验 sha256 → 解压到状态目录 plugins/<id> → 加载 → 出现在平台 chip（不重启进程）
- 更新：版本号更高时按钮变为「更新」，流程同安装，保留 settings
- 卸载：从 chip 移除并删目录；有未完成采集时先等它结束
- 本地安装：选一个 .ofp（zip）文件安装，给离线场景兜底
- 校验失败、清单错误、版本不满足时，错误信息说清哪一条不通过

### FR-6 登录

- 平台 chip 四态：未安装 / 需登录 / 可用 / 出错
- 需登录的平台点击弹面板：说明「用本机已登录的 Chrome 扫码」，提供「打开登录窗口」按钮
- 登录成功后写 cookie 到 <状态目录>/cookies/<插件 id>.json，面板自动变「可用」
- 凭证不落日志、不进接口响应、不在前端展示

### FR-7 刷新与进度

- 手动刷新：按钮触发一轮 pull_many，逐插件推送状态（排队/采集/成功 N 条/失败原因）
- 前端用 SSE 或轮询（二选一，先轮询，简单）
- 采集中允许继续看缓存；不允许并发触发两轮

### FR-8 DEMO 模式

- `--demo` 或 ONEFEED_DEMO=1：插件层零网络，读 fixtures；服务照常起
- 演示前预热：`python -m onefeed --warmup` 拉一轮写到 SQLite 并导出 fixtures
- 断网时页面不能出现任何白屏或未捕获异常

### FR-9 降级与错误

- 单插件失败：该平台 chip 标红，卡片区保留其它平台
- 数据库损坏：自动备份为 .bak 并重建空库，提示用户
- 端口占用、插件目录缺失、fixtures 缺失：启动时给出中文错误与修复命令

### FR-10 设置

- 插件目录、状态目录、registry 地址、每轮条数上限、默认排序
- 修改后立即生效的写「立即生效」，需重启的写「重启生效」

## 5. 非功能需求

| 项 | 要求 |
|---|---|
| 绑定地址 | 只绑 127.0.0.1，默认端口 8787 |
| 首屏 | 缓存命中 < 1.5s 出现首屏卡片 |
| 内存 | 空闲 < 200MB（不含浏览器子进程） |
| 分辨率 | 1366×768 不破版；1920×1080 主演示 |
| 依赖 | 后端 Python 3.12 + fastapi/uvicorn；前端 node 构建后为静态文件 |
| 安全 | 无外网监听；插件代码只在子进程跑；日志不含 cookie |

## 6. 缺字段降级表

| 缺什么 | 怎么显示 |
|---|---|
| 封面 | kind 图标 + 平台色块，不拉伸、不留白框 |
| 作者 | 隐藏作者行，标题上提一档字号 |
| 时间 | 不显示时间（不写「刚刚」） |
| 互动数 | 整块隐藏（不显示 0） |
| 正文 | 卡片只显示标题；详情页显示「原文请跳转」 |
| 评论 | 抽屉里显示「该平台未提供评论」 |
| kind 未知 | 回退为 list 卡，不报错 |

## 7. 验收标准

| 编号 | 验收 | 复现方式 |
|---|---|---|
| AC-V1 | 一条命令起服务，浏览器自动打开，5s 内出现界面 | `python -m onefeed` 计时 |
| AC-V2 | 首屏至少 3 个平台、20 条真实卡片（联网）；缓存命中时不走网络 | 断网重启，仍出卡片 |
| AC-V3 | 五种 kind 各至少一张卡片渲染正确，无布局错位 | 逐 kind 截图存档 |
| AC-V4 | 点击卡片打开详情，评论区在有/无评论两种平台都正常 | B 站（有评论）+ 知乎热榜（无） |
| AC-V5 | 市场页列出 registry 六插件，版本与 sha256 可见 | 打开 /plugins |
| AC-V6 | 删除本地插件 → 市场页装回 → chip 恢复，全程不重启进程 | 手动走一遍 |
| AC-V7 | sha256 不符时拒绝安装并说明原因 | 篡改本地 zip 测试 |
| AC-V8 | 需登录平台显示「需登录」，登录后变「可用」且出数据 | 小红书走一遍 |
| AC-V9 | 单插件抛错时该平台标红，其余平台正常 | 改坏某插件 index.js 触发 |
| AC-V10 | `--demo` 零网络启动出完整界面，无报错 | 断网 + --demo |
| AC-V11 | 1366×768 投屏不破版，详情抽屉不遮列表首列 | 窗口改分辨率看 |
| AC-V12 | 刷新过程中继续下滑不卡，进度逐插件可见 | 点刷新后立即滚动 |

## 9. 数据契约（宿主内部）

- `items`：Item.to_dict() 全字段 + `cluster_id`（去重后同簇共享）
- `runs`：id / started_at / finished_at / plugin / ok / count / error
- `plugins`：id / version / installed_at / enabled / sha256 / source（registry|local）
- 迁移用 `PRAGMA user_version` 递增，不做 ORM

## 10. 依赖与假设

- 插件运行时接口稳定：PluginHost.pull / pull_many / auth / discover（002 §6）
- 状态目录解析沿用 paths.state_root()：ONEFEED_HOME > 可写 ~/.onefeed > 仓库内 .onefeed
- 前端构建在开发机完成，仓库不提交 node_modules；构建产物 dist/ 由服务托管
