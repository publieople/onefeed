## 0. 现在在哪

已完成（2026-11-14 实测）：

- 插件运行时：QuickJS 子进程隔离、能力层 http / cli / browser、64MB 内存上限、worker 软超时跟随宿主
- 六个官方插件：bilibili / douyin / xiaohongshu / juejin / v2ex / zhihu-hot，一次 run 共 58 条、零失败
- 插件仓库：onefeed-plugins，schema + validate.py + build_registry.py + registry.json（目录级 sha256）
- 订阅地址可用：https://cdn.jsdelivr.net/gh/publieople/onefeed-plugins@main/registry.json （main 改版后需 purge）
- 小红书登录态跑通：浏览器截 homefeed + 宿主注入 cookie

没有的东西，也就是这 14 天的全部工作：

| 缺口 | 影响 | 对应里程碑 |
|---|---|---|
| 宿主应用（服务 + 界面） | 现在只有命令行输出，没法给别人看 | M1 |
| 五种 kind 的卡片渲染 | 字段有了，没有"一屏刷完"的观感 | M2 |
| 插件市场安装器 | 现场装插件会失败，讲故事也缺一块 | M2 |
| 登录弹窗 | 换个平台就得找我敲命令 | M3 |
| 去重 / 排序 / 摘要 | 六路混排就是六份列表拼接 | M3 |
| DEMO 兜底 | 断网即翻车 | M4 |

一句话：引擎造好了，车还没装。

## 1. 交付形态（写死，防止临场膨胀）

现场只允许三样东西：本机一条命令、一个浏览器标签、一份兜底录屏。

```
python -m onefeed            # 起服务，自动开浏览器到 127.0.0.1:8787
python -m onefeed --demo     # 零网络，读 fixtures
```

不做：云端部署、Docker、账号体系、多用户、手机端适配、App 打包。评委看到的是投屏上的网页。

## 5. 决赛 5 分钟结构（先写死，后面对稿）

| 时长 | 内容 |
|---|---|
| 0:00–0:30 | 痛点：六个 App、六套推荐、没有一个地方能一次刷完 |
| 0:30–2:00 | 现场演示：一条命令 → 首屏 → 打开一条 B 站视频 → 切到小红书图文 → 用一句话过滤 |

| 3:00–4:00 | 技术：宿主零平台代码、沙箱隔离、凭证不出宿主、失败降级 |

| 4:40–5:00 | 记忆点：这不是一个 App，是一个装得下所有信息流的壳 |

## 6. DoD（每个任务）

1. 有验收命令，自己能跑第二遍
2. 失败路径有降级：该平台显示"暂不可用"，其余照常
3. 提交信息带任务号（例：feat(api): T30 GET /api/feed）
4. tasks.md 勾掉并写日期
5. 新增依赖要写进 README 的快速开始

## 7. 风险

| 风险 | 触发信号 | 预案 |
|---|---|---|
| 现场网络抖 | 刷新转圈 >10s | DEMO 模式 + 已缓存 SQLite，预热脚本 11-27 跑过 |
| 插件安装失败 | 现场 zip 下载 403 / 校验不过 | 预装六个 + 本地 .ofp 包兜底，安装器留"从本地文件安装"入口 |
| 前端拖期 | 11-20 还没看完五种卡片 | 砍 article/short 精细样式，统一回退到 list 卡 |
| 小红书 cookie 失效 | auth 返回 need_login | 扫码流程可现场重来；最坏退回 guest 流（仍出卡片） |
| 评委问合规 | 提问"这不算爬虫吗" | 照着 DISCLAIMER 与 002 §11.2 的诚实口径答，不承诺免责 |
| 抖音风控变严 | 连续两次 0 条 | 演示只用 B 站 + 小红书 + 热榜三类，抖音留"没接上也好看"的空态 |
