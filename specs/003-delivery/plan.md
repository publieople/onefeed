## 0. 现在在哪

已完成（2026-11-14 实测）：

- 插件运行时：QuickJS 子进程隔离、能力层 http / cli / browser、64MB 内存上限、worker 软超时跟随宿主
- 六个官方插件：bilibili / douyin / xiaohongshu / juejin / v2ex / zhihu-hot，一次 run 共 58 条、零失败
- 插件仓库：onefeed-plugins，schema + validate.py + build_registry.py + registry.json（目录级 sha256）
- 订阅地址可用：https://cdn.jsdelivr.net/gh/publieople/onefeed-plugins@main/registry.json （main 改版后需 purge）
- 小红书登录态跑通：浏览器截 homefeed + 宿主注入 cookie
- 宿主后端三件：T29 存储 / T30 只读 API / T31 单命令入口，测试 24 + 25 + 7 项全过，端到端 12 条真数据打通
- 视觉：三套对比稿已出（design/mockups.html），推荐 A 克制企业白

没有的东西，也就是这 14 天的全部工作：

| 前端一行代码都没有 | `python -m onefeed` 打开是提示页，没法给别人看 | M1 |

## 1. 交付形态（写死，防止临场膨胀）

现场只允许三样东西：本机一条命令、一个浏览器标签、一份兜底录屏。

```
python -m onefeed            # 起服务，自动开浏览器到 127.0.0.1:8787
python -m onefeed --demo     # 零网络，读 fixtures
```

不做：云端部署、Docker、账号体系、多用户、手机端适配、App 打包。评委看到的是投屏上的网页。

## 2. 里程碑（2026-11-14 重排）

## 5. 决赛 5 分钟结构（先写死，后面对稿）

| 时长 | 内容 |
|---|---|
| 0:00–0:30 | 痛点：六个 App、六套推荐、没有一个地方能一次刷完 |
| 0:30–2:00 | 现场演示：一条命令 → 首屏 → 打开一条 B 站视频 → 切到小红书图文 → 用一句话过滤 |
| 2:00–3:00 | 插件：现场装一个插件，20 行代码接一个新平台（vibe coding 卖点） |
| 3:00–4:00 | AI 为什么非它不可：同题合并（六个平台在讲同一件事）、平台内归一排序、自然语言过滤 |
| 4:00–4:20 | 技术：宿主零平台代码、沙箱隔离、凭证不出宿主 |
| 4:20–4:40 | 边界与诚实：只读、本地、插件作者行为不由本项目承担 |
| 4:40–5:00 | 记忆点：这不是一个 App，是一个装得下所有信息流的壳 |

注意 3:00–4:00 这 60 秒是 2026-11-14 新增的：原来没有这段，评委会问「这跟 RSS 阅读器有什么区别」。
