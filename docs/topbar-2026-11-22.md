# 顶栏重做记录（2026-11-22）

目标：把两件「不优雅」一起改掉 —— 刷新进度不再占信息流整行、关掉后不留 40px 空位；采集与统计从一行裸文本收成组件，顶栏右组变成一排同规格的件。

用户原话：「现在这个更新进度条占用了主视图整行，而且关闭后还会预留出这行的空位，很不优雅。改成：按完刷新按钮后，从刷新按钮左侧弹出一个进度条；同时把原本的采集和统计也重新设计一下，做成组件式的，让顶栏看起来更自然。」

## 1. 改之前的三处病

| 位置 | 代码 | 症状 |
| --- | --- | --- |
| `web/src/components/RefreshBar.tsx:58` | `if (idle \|\| hidden) return <div className="mt-4 h-10" aria-hidden="true" />;` | 没在刷新也钉着一行 40px |
| `web/src/components/TopBar.tsx` 页头下缘 | `absolute inset-x-0 -bottom-px` 的 2px 进度线 | 同一件事有第二份进度在说话 |
| 同上 | 裸文本 `{count} 条 · 最近采集 HH:MM` + `w-11` 的 done/total | 宽度随字数跳；空着也占位；点不动 |

## 2. 五处实现

### 2.1 进度件（web/src/components/RefreshProgress.tsx，新）

一件三态，全是绝对定位，长出和收起都不推动任何东西：

```ts
const show = Boolean(progress) && !(dismissed > 0 && dismissed === started)
  && (live || (finishedAt > 0 && lingered !== finishedAt));
```

| 状态 | 长相 | 时长 |
| --- | --- | --- |
| 运行中 | `⟳ 正在抓 知乎 5/7 99s ×`，胶囊内一条左侧填充随 done/total 走 | 到本轮结束 |
| 整理中 | `整理中 马上好` | 相位机 settling 期间 |
| 结束 | `+47 条 刚放进来了` / `没有新增 抓完了`（附着），失败多一枚 `!` | 6 秒（hover 暂停） |

三个不显眼但必须有的约定：

- **收起只收本轮**：localStorage 存的是 `started_at`，下一轮天然不同，不用清理；「重试失败」或运行中再点刷新（`hint` 变）会把它重新亮出来并 `ring-2 ring-accent/35` 闪 900ms —— 点了要有回应，而不是「点了没反应」。
- **失败细节不进行内**：点 `!` 走 `onefeed:toast`，文案 `N 个平台没抓到：A、B`，动作「重试失败」回调 `onRetry(failed)`。行内一展开，行高一变正文就跳。
- **aria-live="polite" + aria-busy**：读屏用户能听到进度变化。

### 2.2 宽度补间：grid 的 0fr/1fr 在这儿是错的

第一版照常见写法用 `grid` 包一层，`grid-template-columns: 0fr / 1fr` 做开合。真机上胶囊只剩约 18px 宽、文字全被裁掉。

原因：这套写法靠「1fr 的子项被压缩到 0」来收宽度，但父级是 `position: absolute`，`1fr` 没有可参照的容器宽度，退化成 `min-content`；外层又 `overflow: hidden`，于是内容直接被切。

改成：内层 `w-max` 拿自然宽度，`ResizeObserver` 量 `offsetWidth` 存进 state，外层 `style={{ width: show ? width : 0 }}` + `transition-[width] duration-300`。内容从「5/7」变成「+47 条」时宽度会重测，补间跟着走。

### 2.3 顶栏右组（web/src/components/TopBar.tsx）

顺序即因果：`[刷新 ↻]` → `[采集胶囊]` → `[主题] [市场] [设置]`。进度件是刷新按钮左侧的同级绝对定位件，所以不会压住采集胶囊；右组其余三件与刷新按钮同为 `h-9 w-9` 的圆形按钮，采集胶囊同为 `h-9`，一排下来基线一致。

`clickRefresh` 运行中不再 `querySelector("[data-refresh-bar]")` + `scrollIntoView`（把人滚到别处是错的方向，进度本来就该在按钮旁边），改为 `setHint((n) => n + 1)`。

删掉的：裸文本 span、`w-11` 的 done/total 占位、页头下缘 2px 进度线、`timeOf()`。

### 2.4 采集胶囊（web/src/components/CollectPill.tsx，新）

一枚 `h-9` 胶囊：新鲜度圆点（有条目 = `bg-accent`，空库 = `bg-line`）+ `1379 条`（`tabular-nums`）+ `· 21:24`（`hidden sm:inline`）+ `ChevronDown`（展开时转 180°）。

浮层 `w-[272px]`，按 `last_fetched_at` 降序列七个平台：色点（`platform(id).tint`）+ 名称 + 条数 + 时刻，底部一行「最近采集」+ `1 分钟前`（`agoOf` 出「刚刚 / N 分钟前 / N 小时前 / N 天前」）。

两条规矩：
- `role="dialog"` 的组件必须调 `useModalScope(open)` —— `tests/test_interaction.py` 的 `test_every_dialog_takes_over_the_hotkey_stack` 会扫全部 dialog，漏了就是 28/29。
- `pointerdown` 点外面关、`Escape` 关，关的时候把焦点还给胶囊按钮。

### 2.5 信息流（web/src/pages/FeedPage.tsx）

`<RefreshBar …/>` 整块删除，原位留两行注释说明进度去哪了；顺手删掉只服务于旧状态条的 `played` state（`playedSeq` 留下，它认的是 `refreshSeq`）。

深处那枚「有 N 条新内容」胶囊保留 —— 它是刷新完成后唯一保底入口，和顶栏无关。

## 3. 取舍

| 选择 | 为什么 |
| --- | --- |
| 按钮左侧，而不是顶栏中间 / 页面底部 | 点哪里、进度就从哪里长出来；绝对定位所以不长宽任何东西 |
| 结束停 6 秒 | 结果是「一次性消息」，看清就收；hover 暂停，X 只收本轮 |
| 结果态不在顶栏放「看新内容」 | 深处胶囊已经承担这个入口；顶栏再把「刷新」和「去看」混在一起，「+47 条」就变成两个意思 |
| 量宽补间，而不是 `scaleX` / `max-width` | `scaleX` 会压扁文字；`max-width` 在内容变短时会先裁后露。宽度本来就在变，只能量 |

## 5. 已知边界

- 窄屏 < 640px：胶囊只留「正在抓 5/7」，平台名和秒数靠 `hidden sm:inline` 收掉；`max-w-[min(62vw,440px)]` 兜住极端长名字。
- 6 秒内的连点只闪不重播：`hint` 只让胶囊重新亮，不重开一轮；真刷新仍要等按钮不在运行态。
- 「收起」是按 `started_at` 记的，跨轮不串；换浏览器/清 localStorage 才会重来。
- `web/dist` 随仓库入库（一直如此），所以提交里会带一整套资源哈希变化。
