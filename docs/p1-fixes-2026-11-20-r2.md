## 二、逐条落地

### 1. Lenis 改成单 rAF（`web/src/motion/useSmoothWheelScroll.ts`）

原来每个容器 `new Lenis({ autoRaf: true })`，各起一条 rAF；首页 2 条、详情+AI 右栏 3 条，空闲时也在满帧空转。

现在：

- `autoRaf: false`，模块级一条 `function pump(time)` 驱动全部实例：`instances.forEach((lenis) => { lenis.raf(time); if (lenis.isScrolling) active = true })`。
- 连续 `IDLE_FRAMES = 6` 帧没有实例在滚就 `cancelAnimationFrame`，rAF 归零；`kick()` 由滚轮捕获和 `scrollInstant` 唤醒。

实测（1440×900，首页 2 实例，3 秒窗口）：

| | rAF 回调 | CPU |
| --- | --- | --- |
| 修前 | 149–151 /s | 6.1–7.6% |
| 修后 | **0 /s** | **0.4%** |
| reduce（0 实例） | 0 /s | 0.4% |

顺带改掉 C-03：MutationObserver 只看 `record.addedNodes` 与 characterData 命中的最近容器，120ms 合批；resize 只对相关容器调 `instances.get(el)?.resize()`（原来每次全文档 scan + 全实例 resize）。

### 2. 栏宽补间不再翻列（`web/src/layout/gridFreeze.ts` + `useGridCols.ts` + `Shell.tsx`）

根因：`useGridCols` 的 ResizeObserver 每帧按当时宽度算列数，240→64 途中会先变宽再跳到更窄。

现在 `Shell` 在 `leftW`/`railOpen` 变化时算目标内容宽度 `base - dLeft - dRight`，`freezeGridWidth(..., DUR.page + 80ms)` 冻结；`useGridCols` 用 `frozen ?? width` 作为有效宽度，补间结束自然解除。

实测收起：

```
3c / 370.7 → 4c / 298.3 → 4c / 316.4 → 4c / 317
cols_set = [3, 4]   # 只在起点翻一次
```

修前是 `3c/370.7 → 3c/426.4 → 4c/317`（260ms 内两次变宽，卡片先胖再瘦）。展开反过来：`4c/317 → 3c/381 → 3c/370.7`。

> **已被取代（2026-11-20 夜，`docs/grid-cols-stable-2026-11-20.md`）**：冻结只盖住 340ms 的补间，补间一结束列数照样按新宽度重算 —— 收左栏内容 +176px，仍会从 3 列 370 翻成 4 列 317，用户看到的还是「点一下侧栏整屏重排」。现在改为**列数只跟窗口宽度走**：`useGridCols` 不再用 ResizeObserver 观察网格自身，`gridFreeze.ts` 整条删除，侧栏开合期间卡片连续变宽变窄但换行位置不动。本节实测数据只说明「补间中不再闪两下」，不再代表最终行为。

### 4. 模态锁页面滚动（`web/src/motion/useScrollLock.ts`）

新增计数式 `useScrollLock(active)`：`depth === 1` 时给 `document.documentElement` 设 `overflow: hidden` + `scrollbarGutter: stable`，归零还原。接在确认框（`ConfirmHost`）、快捷键帮助、灯箱、收藏备注对话框上，替换掉原来只锁 `body` 的手写代码（`body` 锁不住 `html`，实测灯箱打开页面仍 0→175）。

另一个坑：`web/src/motion/useScrollSpeedCap.ts` 自己 `scrollBy` 做速度上限，光锁 `overflow` 拦不住它 —— 现在 `isPageScrollLocked()` 为真时直接 `preventDefault` 并跳过 `scrollBy`。

实测（滚轮 600px）：

| 场景 | 滚动前 | 滚后 | html overflow |
| --- | --- | --- | --- |
| /settings「清除所有 key」确认框 | 614 | **614** | hidden |
| 快捷键帮助层 | 400 | **400** | hidden |
| 灯箱 | 0 | 0 | hidden |
| 关闭确认框后再滚 300 | 614 | 914（恢复） | visible |

### 5. 侧栏到底放行滚轮（I-04）

`overscroll: true` 单独不够：Lenis 的 `composedPath().slice(0, indexOf(rootElement))` 看不到 wrapper 自身，打在 wrapper 上的 `data-lenis-prevent` 也不生效。

做法：document 捕获阶段读 `scrollHeight - clientHeight`，到顶/到底且方向朝外时给**实际滚轮目标**打一个 `data-lenis-prevent`（`setTimeout(..., 0)` 立刻摘掉），这一下交给页面原生滚动。

同时删掉 7 个滚动容器上的 `overscroll-contain`（`AgentSidebar` ×2、`AgentThread`、`FavoritesList`、`RightRail`、`SavedList`、`SummaryList`）—— CSS 的 `overscroll-behavior: contain` 会截断滚动链，即使放过 Lenis，页面也滚不动。

实测：列表到底（568/568）后滚 400 → `window.scrollY` **0 → 400**；列表中段滚 300 → 列表 120→465、window 仍 0。

### 6. test_api 假红（C-01）与 preflight

`tests/test_api.py:80` 还在断言「feed 首条按时间倒序」，而 `8b217c3` 起 `onefeed/store.py` 的 `page()` 已改成平台轮转交错，断言必然失败 —— 没人跑全量所以一直没暴露。

改成三条业务断言：不重不漏、每个平台内部按时间倒序、相邻两条不同平台（交错）。

新增 `scripts/preflight.ps1`：pytest → `tests/run_all.py --offline` → `node web/scripts/check-ui.mjs` → `npm run build`，任一红即停。先 `uv run --offline --with pytest python -c "import pytest"` 探缓存，没有才联网（本机代理常关）。

## 五、残留与未验证

- **左栏补间在 headless 仍不是 60fps**：稳态 53–66ms/帧、首轮一次 186ms。headless 走 SwiftShader 软件光栅重画整列，真机 GPU 未验；要彻底消掉得让内容列在补间期间不重排（宽度一次到位 + 内容淡入，或纯 transform 覆盖），会牺牲「内容跟着栏宽连续收放」的观感。
- 补间只有 5–14 个不同宽度值（260ms 应有约 16 帧），中间档被长帧吃掉，肉眼接近台阶。
- 右栏打开首轮仍有 80ms 单帧（第二次起 26.7ms），冷启动成分未拆。
- 未测 Safari / Firefox；窄屏（<960）两栏都不渲染，只走抽屉。
- 评审里 C-06（左右方向代价不对称）只做了缓解，没有改结构。
