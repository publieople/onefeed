## A. 值得改（本轮已修 3 条）

### A1 转场结束后没有接管焦点

- **现象**：点卡片进详情，卡片这个 `<a>` 随路由卸载，焦点掉回 `body`；键盘 / 读屏用户下一次 Tab 从页头重新开始。返回同理。
- **证据**：`web/src/motion/nav.ts:130-142`（`done()` 只清名字和类，全函数无 `.focus()`）；`web/src/pages/ItemPage.tsx:1175-1181`（`h1` 无 ref、无 `tabIndex`）；全站 25 处 `.focus(` 全是弹层 / 输入框 / roving tabindex，没有一处是路由级。
- **指南**：`same-document-transitions`，**MANDATORY Accessibility Routing**。
- **改法**：`ItemPage` 给 `h1` 加 `ref` + `tabIndex={-1}` + `outline-none`，在 `item.id` 变化的 effect 里 `focus({ preventScroll: true })`（延后一拍，别和转场抢帧）；`FeedPage.restoreAnchor`（`:65-84`）找到卡片后把焦点还给卡片的 `a`。
- **风险**：低。只 `preventScroll`，不要 `scrollIntoView`；`outline-none` 只给 h1，按钮的 focus ring 不动。

### A2 两处 Enter 没判输入法组合态

- **现象**：中文输入法里 Enter 是「确认候选词」。这两处会在选词那一下直接提交。
- **证据**：`web/src/components/AgentConsole.tsx:266-271`（Agent 的自由回复输入框，Enter → `send()`）；`web/src/components/ui/Confirm.tsx:187-192`（`requireTyping` 输入框）。
- **对照**：`ItemChat.tsx:299` 已经正确写了 `!event.nativeEvent.isComposing`。
- **指南**：`ime-safe-enter-submit`。
- **改法**：先 `preventDefault()`，再 `if (e.nativeEvent.isComposing) return;`；Safari 旧版 `compositionend` 早于 keydown，可再加 `keyCode === 229` 兜底。
- **风险**：极低，各 2 行。AgentConsole 这条在演示里最可能翻车——Agent 反问一句，用户用中文答。

### A3 滚动条只有 WebKit 前缀

- **现象**：Chrome/Edge 是 10px 细条，Firefox 是系统默认宽条；暗色下尤其割裂。拇指色 `--c-line`（230,224,212）在纸色（253,251,247）上对比度约 1.2:1，低于 3:1。
- **证据**：`web/src/theme.css:201-213` 只有 `::-webkit-scrollbar` / `-thumb` / `-track`。
- **指南**：`customize-scrollbar-color-and-thickness`（**MANDATORY** 用标准属性；WebKit 写法要放进 `@supports not (scrollbar-color: auto)` 并在其中把 `scrollbar-width` 重置为 `auto`）。
- **改法**：`html { scrollbar-width: thin; scrollbar-color: rgb(var(--c-fade)) transparent; }`，WebKit 三块包进 `@supports not`。拇指用 `--c-fade`（≈3.3:1 亮 / 4.7:1 暗）而不是 `--c-line`。
- **风险**：低。Firefox 上不再有系统宽条；三处 `[scrollbar-width:none]`（`RightRail.tsx:98`、`AgentSidebar.tsx:254`、`ui/TabRail.tsx:529`）本来就只影响 Firefox，无需改。

## B. 可选：收益明确但不必赶在比赛前

### B1 原生 `<dialog>` 迁移（分两批）

- **现状**：5 处自绘 `role="dialog" aria-modal="true"`——`AgentSurface.tsx:165`、`ItemPage.tsx:261`（灯箱）、`ItemPage.tsx:1619`（收藏框）、`ShortcutHelp.tsx:77`、`ui/Confirm.tsx:159`；配套手写 Tab 陷阱、Esc、`useScrollLock`（`html.style.overflow = "hidden"`，`useScrollLock.ts:23`）。
- **指南**：`dialog`——「**MANDATORY: no `role="dialog"` or `aria-modal`; the native modal already provides them**」；「**DON'T** add … a focus trap … or an `Esc` handler」；「**DON'T** lock scrolling with `overflow: hidden` … on `html` or `body`」（会挪掉根滚动条、造成横向位移）。
- **改法**：第一批 `Confirm` + `ShortcutHelp`（不依赖 View Transition）：`<dialog>` + `showModal()`、`dialog:modal { overscroll-behavior: contain }`、`::backdrop`、`autofocus` 放「取消」，删 `role/aria-modal/trap/Esc/useScrollLock`。第二批灯箱与收藏框；`AgentSurface` 面板要挂 `of-agent` 名字，留到最后单独验证。
- **收益**：少约 150 行手写焦点 / 滚动代码，Safari 返回手势、top layer 免费拿到。
- **风险**：中，视觉（`backdrop-blur`、`z-[60]`）要逐个回归。

### B2 首屏外的卡片加 `content-visibility`

- **证据**：`FeedPage.tsx:459-471` 一次渲染 30 张卡 + 「加载更多」，库里 1155 条；全站 `content-visibility` 0 处。
- **指南**：`defer-rendering-heavy-content`——「**MANDATORY**: You MUST pair `content-visibility: auto` with `contain-intrinsic-size`」，否则离屏高度塌成 0，滚动直接跳。
- **改法**：只给第 7 张之后、且 `layoutOn === false` 的卡片外层加 `style={{ contentVisibility: "auto", containIntrinsicSize: "auto 340px" }}`。`layoutOn`（≤12 张）时不加，免得和 FLIP 冲突。
- **风险**：中。改完必须用键盘从头 Tab 到尾，确认离屏边界顺序可达（指南的 MANDATORY 验证）。

### B3 全局「减少动态效果」一刀切

- **证据**：`theme.css:127-139` `*, *::before, *::after { animation-duration: 0.001ms !important; transition-duration: 0.001ms !important; }`。
- **指南**：`motion`——「**DO NOT** globally apply `animation-duration: 0.01ms;` as it can cause certain animations to become more jarring.」也要求保留颜色类过渡。
- **改法**：删全局块，改为已有的三处定向块（`:530` 抽屉、`:606` 侧栏、`nav.ts` 里 reduce 直接不跑 VT）再补 `.rise / .fade-in / .sheet-in / .drawer-in` 的 `animation: none`；颜色过渡保留。注意每个被关掉的动画，元素基础样式必须是「终态可见」，不能停在 `opacity: 0`。
- **风险**：中低，需在 reduce 下逐页看一遍。

### B4 `scroll-padding-top`

- **现状**：顶栏 `sticky top-0` 高 56px（`TopBar.tsx:43-49`），全站无 `scroll-padding-top`。
- **指南**：`state-aware-sticky-headers` 提到 WCAG 2.4.11——聚焦元素不该被吸顶栏完全盖住。
- **改法**：`html { scroll-padding-top: 72px; }`。设置页已有 `scroll-mt-24`，这条是给 Tab 焦点和浏览器原生滚动用的。
- **风险**：极低。

### B5 撤销 toast 会自动消失

- **证据**：`App.tsx:76-80` 带 action 的 toast 5200ms 后清空；无关闭按钮；焦点在按钮上时也照常倒计时。
- **指南**：`persistent-toast-notifications`——「Prefer persistent toast notifications that remain present until they are dismissed」；若限时，须在焦点位于 toast 控件上时暂停。
- **改法**：带 action 的 toast 不自动消失（或 12s），加 `Close`；`onFocus` 暂停计时。
- **风险**：低，但要改 MarketPage / 收藏的撤销路径。

### B6 `findLast`

- `AgentComposer.tsx:17` `[...turns].reverse().find(...)`、`AgentProvider.tsx:587` `[...events]` 后 reverse+find → `findLast`。收益微小，顺手改即可。

## C. 不建议动

| 项 | 为什么不 |
| --- | --- |
| `<input type="checkbox" switch>` | 指南自己写明 **Chrome / Edge / Firefox 均不支持**，只有 Safari 17.4+；换过去等于给主力浏览器套 polyfill。现有 `role="switch" aria-checked`（`AiProviders.tsx:107`、`SettingsPage.tsx:966`）语义已经正确。 |
| Speculation Rules 替手写预取 | 需要后端给出可预渲染的独立 URL 与缓存头；比赛前动它只会引入不确定性。 |
| 吸顶栏 `scroll-state` 查询 | 需要把边框/背景移到子元素、还要给父级 `overflow-anchor: none`；收益只是「滚动时多一条阴影」，与演示无关。 |
| `@media (forced-colors: active)` 全套 | 高对比模式受众很窄，而全站依赖 CSS 变量与细边框，改造面大。 |

### A 档实测（2026-11-22 16:5x，Chrome 1440×900，1155 条真实数据）

用 `probes/probe_a11y_focus.py` 在页内取 `document.activeElement`，不靠肉眼：

| 断言 | 实测值 |
| --- | --- |
| 滚动条走标准属性 | `scrollbar-width: thin`、`scrollbar-color: rgb(139,133,120) rgba(0,0,0,0)`（= `--c-fade`） |
| 进详情焦点落 h1 | `tag: H1`、`isH1: true`、`tabIndex: "-1"`、`scrollY: 0`（未把页面拽动） |
| 返回焦点回卡片 | `tag: A`、`holder: xiaohongshu:note:6afef19f…`、`same: true` |
| 回卡片后能继续用 | 焦点上再按 Enter → 重新进详情，路径与首次一致 |

**一个必须说清的边界**：上面「返回」走的是页面左上角那个「返回」按钮。浏览器自带的后退键走不到这条路径——后退时 `FeedPage` 拿到的 `location.state` 是 feed 自己那条记录（无 `fromId`），`restoreAnchor` 直接 return，所以焦点会落回 `body`、滚动也会被 `App.tsx` 的 `scrollTo(0)` 拉回顶部。这不是本条改动引入的，是「导航上下文只存在 location.state 里」这个旧设计的结果，补它要动路由状态（例如把来源 id 存进 sessionStorage 并在 popstate 时读回），超出本次指南审计范围，单独列为后续项。
