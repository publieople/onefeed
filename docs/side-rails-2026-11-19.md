# 两侧空间怎么用：左 Agent 工作台 + 右「稍后再看」（方案，2026-11-19）

## 1. 现状：空在哪、为什么

页面的内容列是写死的居中最大宽：`<main class="mx-auto w-full max-w-[1180px] px-6">`
（`web/src/App.tsx:185`），顶栏也跟着 `max-w-[1180px]`（`web/src/components/TopBar.tsx:48`）。

| 视口宽 | 内容列 | 两侧各留 |
|---|---|---|
| 1280 | 1180 | 50 |
| 1440 | 1180 | 130 |
| 1920 | 1180 | 370 |
| 2560 | 1180 | 690 |

1440 以上留白就开始明显，2560 上左右各有近 700px 纯背景——不是「留白呼吸感」，
是一整块没用上的产品面积。而现在的功能又在往「工作台」方向长（Agent 会话、收藏、同题对比），
这些恰恰需要常驻的位置。

## 2. 三条路线

| 路线 | 做法 | 问题 |
|---|---|---|
| A 对称三栏常驻 | 1440 起左 288 + 中 + 右 320 都常驻 | 中栏被压到 700 出头，hero 视频变窄、卡片从 3 列掉到 2 列，共享元素几何全变 |
| B 两侧纯浮层 | 不占位，按钮唤出 | 视觉上仍然空，用户第一眼看到的还是一大片背景 |
| **C 左常驻 + 右抽屉（推荐）** | 左栏进栅格常驻；右栏默认浮层、1800 以上才常驻 | 中栏宽度只在跨断点时才变，且变化是离散的，不会边拖边抖 |

选 C 的核心理由：**内容列的宽度稳定性优先级高于视觉对称**。详情页的 hero、卡片等高契约
（标题固定 46px、meta 槽 43px）、共享元素代位盒子的几何计算（`web/src/motion/ghost.ts:16-39`
里写死 `CONTENT_MAX = 1180`）全都依赖内容列宽度。右栏一旦参与栅格，收起/展开就会让视频
重新布局，共享元素转场也会错位。

## 3. 推荐方案

### 3.1 三区结构

```
┌──────────────┬───────────────────────────────┬──────────────┐
│ 左：Agent 工作台 │ 中：信息流 / 详情（≤1180，居中）      │ 右：稍后再看     │
│ 288（常驻）     │ 卡片 2–3 列 / 详情 hero           │ 340（抽屉/常驻）  │
│ 会话史 + 收藏入口 │                               │ 稍后再看 / 同题   │
└──────────────┴───────────────────────────────┴──────────────┘
```

- 左栏进栅格（`grid-cols-[288px_minmax(0,1fr)]`，≥1200），宽度离散切换，不做持续动画。
- 右栏默认 `position: fixed` 抽屉（不挤压内容），≥1800 才转为栅格第三列常驻。
- 中列内容仍 `max-w-[1180px] mx-auto`：宽屏上多出来的余量变成两侧呼吸，而不是把卡片拉胖。

### 3.2 断点

| 视口 | 左栏 | 右栏 | 内容列实宽 |
|---|---|---|---|
| ≥1800 | 288 常驻 | 320 常驻 | ≤1180 |
| 1440–1799 | 288 常驻 | 340 抽屉（`]` / 工具栏按钮） | ~1072–1132 |
| 1200–1439 | 64 图标轨（悬停/聚焦展开 288 浮层） | 340 抽屉 | ~1056–1136 |
| 1024–1199 | 64 图标轨 | 340 抽屉 + 遮罩 | ~880 |
| <1024 | Sheet（左侧滑出） | Sheet（右侧滑出） | 满宽 |

卡片列数沿用现在的 `md:2 xl:3`；只有一种情况要动：1440 段左栏常驻后中列约 1072，
若实测 3 列显挤，就把 3 列阈值从视口 1280 提到 1400（`web/src/pages/FeedPage.tsx` 卡片网格那行）。

### 3.3 左栏：Agent 工作台

继承 `/agent` 页左栏已经验证过的信息结构（`web/src/pages/AgentPage.tsx:68-100`），抽成
`AgentSidebar`，两处复用：

1. 顶部：「+ 新对话」+ 会话搜索（本地过滤标题，P2）
2. 会话列表：今天 / 昨天 / 更早分组；当前线程高亮；每条 = 标题（截断）+ N 轮 + 相对时间；
   悬停出现「重命名 / 删除」（P2，需要新接口）
3. 进行中：有 run 在跑时置顶一条「正在跑：<这一轮的输入>」+ 停止按钮
4. 收尾：收藏/稍后再看计数入口、快捷键帮助（`?`）、设置
5. 空态：「还没聊过。按 / 说一句，这里就会记下来。」

不放：导航菜单（顶栏已有）、装饰性统计数字。

### 3.4 右栏：「稍后再看」槽位

右栏在详情页已经存在（`web/src/pages/ItemPage.tsx:923` 的 `380px` Agent 栏），这次把它升级成
**一个槽位、三个 tab**，信息流页与详情页共用同一个组件：

| Tab | 内容 | 数据 |
|---|---|---|
| 稍后再看 | 已收藏条目：缩略图 + 标题 + 平台 + 加入时间；hover「移出」「打开」；顶部计数与「清空已读」 | `item_marks.saved`（需加 `saved_at` 排序） |
| AI 助手 | 现成 `AgentRail` 内容 | 已有 |
| 同题 | 这条在别的平台也出现（`siblings`）+ 各平台热度的简单对比 | `/api/item/{id}` 已返回 |

详情页默认 tab = AI（保持现状），信息流页默认 tab = 稍后再看。
「稍后再看」空态：「卡片上的星标就是这里。看到想留的，点一下星。」

## 4. 需要的数据改动

1. `item_marks` 增加两列：`saved_at INTEGER NOT NULL DEFAULT 0`、`note TEXT NOT NULL DEFAULT ''`
   （`onefeed/store.py:161-167`）。迁移用 `PRAGMA table_info` 判断后 `ALTER TABLE`，幂等。
2. `mark_item()`：`saved` 从 false→true 时写 `saved_at = now`，true→false 时清 0
   （`onefeed/store.py:664-680`）。
3. `page(saved=True, sort="saved")`：排序键 `m.saved_at DESC`，缺省时回落到现有 freshness。
   `GET /api/feed?saved=1&sort=saved`（`onefeed/api.py` feed 路由已有 `saved` 参数）。
4. P2：`PATCH /api/agent/threads/{id}`（重命名）、`DELETE`、`/api/agent/threads?q=` 搜索。

## 5. 交互与实现细节

- **键盘**：`[` 开合左栏（≥1200 才有可开合状态）、`]` 开合右栏；两个都走
  `useHotkeys("dialog")` 的作用域栈，Esc 关最上层（`web/src/motion/useHotkeys.ts`）。
  `j/k` 列表导航不受影响。
- **焦点顺序**：DOM 顺序就是 左 `<aside>` → `<main>` → 右 `<aside>`；两侧各用
  `aria-label`（「Agent 工作台」「稍后再看」），不做焦点陷阱（不是模态）。
- **转场**：左栏 64↔288 离散切换（内容 fade `DUR.micro`），不做宽度动画——宽度动画会让
  卡片逐帧重排。右栏抽屉用 `SPRING_SOFT` 从右滑入，<1200 带遮罩；打开/关闭都跑
  `runNav("tab")`，跟现有 Agent 唤起器一致（`web/src/motion/nav.ts`）。
- **内容宽度的单一来源**：`ghost.ts` 的 `contentEdges()` 改为优先读 `#main` 的实际
  `getBoundingClientRect()`，常量只作兜底，否则左右栏一开，代位盒子与唤起器就错位。
- **滚动**：三个区域各自滚动，`overscroll-contain`；顶栏 sticky 只覆盖中列上方，
  两侧栏 `sticky top-[76px] h-[calc(100vh-96px)]`（照抄 `web/src/agent/AgentRail.tsx:21-25`）。
- **性能**：左栏一次 `GET /api/agent/threads?limit=20`（SQL 已经在 10ms 内）；右栏一次
  `/api/feed?saved=1&limit=20`；缩略图懒加载；两侧栏都只在首次展开时拉数据。

## 6. 与现有 Agent 三形态的关系

现在 `mode` 只有 closed / sheet / rail（`web/src/agent/AgentProvider.tsx:738`）。改造后：

- 信息流页：左栏常驻会话史；唤起器仍在底部（胶囊），打开是 sheet——**不改**。
- 详情页：左栏仍在（1440 起），右栏槽位默认 AI，与现在的 rail 同宽（340 替代 380）。
- `/agent` 全页形态保留：它是「专心聊」的场景，左栏 + 大对话区；抽屉/右栏是「边看边聊」。
  两者通过「展开成全页」按钮连通（现在已有「对话」入口的雏形）。

## 7. 三批落地

**批次 1｜左栏（约 0.5 天）**
抽 `AgentSidebar` → App 栅格接入 → 断点（288 / 64 / Sheet）→ 顶栏改满宽 → `ghost` 动态测宽
→ 验收：1440 与 1920 下内容不重叠、卡片列数正确、共享元素转场仍从卡片正确放大。

**批次 2｜右栏稍后再看（约 1 天）**
`item_marks` 迁移 + `saved_at` → `sort=saved` → `SavedRail` 抽屉（含移出/撤销）→
验收：星标后 1 次点击在右栏出现、移出后立刻消失且 5s 内可撤销、刷新顺序稳定。

**批次 3｜槽位合并 + 打磨（约 1 天）**
详情页右栏三 tab（AI / 稍后再看 / 同题）→ `[` `]` 快捷键 → 空态文案 → 窄屏 Sheet →
静态守门测试（`tests/test_interaction.py`）+ 真机 1440/1920/2560 三档截图。

## 8. 风险与不做什么

- **中列变窄**：1440 段内容从 1180 掉到约 1072，卡片 3 列偏挤 → 必要时把 3 列阈值提到 1400；
  hero 视频宽高比不变，但共享元素终点会变，转场要重测。
- **三处滚动**：容易出现「滚到一半外层跟着动」——统一 `overscroll-contain`，并禁用
  `html` 的平滑滚动对两侧栏的影响。
- **不做**：不做「左栏收纳所有导航」（顶栏已经够用）、不做视觉对称硬撑三栏、不做
  两个栏同时可拖拽调宽（收益低、回排 bug 多）。

## 9. 验收清单

1. 1920 下左右两侧不再有大片纯背景；1440 下左栏可见、中列不窄于 1000。
2. 三个断点（1024 / 1440 / 1920）下内容列不溢出、不出现横向滚动条。
3. 从左栏点开旧对话，结果卡片与轨迹完整（依赖已修好的历史回放）。
4. 右栏「稍后再看」与卡片星标双向同步，取消收藏后条目立刻消失。
5. 详情页右栏 tab 切换不重载视频；共享元素转场仍从卡片正确放大。
6. 键盘：`[` `]` 开合、Esc 关闭、Tab 顺序为 左 → 中 → 右。
7. `pytest`、`check-ui`、`npm run build` 全过，并补 3 条静态守门
   （左栏栅格、右栏抽屉不改内容宽、ghost 动态测宽）。
