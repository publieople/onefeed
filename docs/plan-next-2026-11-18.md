- 日期：2026-11-18

- 技术栈不动：React 18 + react-router 6 + framer-motion 11 + Tailwind 3 + FastAPI

## 0. 一页结论

四件事被低估了，先说清楚，因为它们决定排期：

1. **共享元素不是「多写几个 viewTransitionName」**。现在全站只有一个名字 `of-card`（`web/src/navTransition.ts:22-40`），而且是把整张卡片快照长大成整页——它看起来像变形，实际是「整页缩放」，因为你共享的是容器而不是内容。真正沉浸式要共享的是**媒体框 + 标题**两个元素，其余内容在转场结束后错峰进入。
2. **流式总结的瓶颈在后端，不在前端**。`onefeed/ai.py:144-161` 是阻塞 `urllib` + `response_format: json_object`，一次返回整包；`onefeed/api.py:463-486` 也是 `def`（同步）返回 dict。前端再怎么改也流不起来。而且 **json_object 与 stream 在很多 provider 上不兼容**，所以协议要从 JSON 改成「行式」，由服务端边流边解析成结构化字段。
3. **停止按钮是假的，根因是取消标志没人读**。`RunState.cancel` 只赋值（`onefeed/agent_runtime.py:56,71-78`），循环里没有检查点；取消接口直接 `finish_agent_run("cancelled")` 却不发 `done`（`onefeed/api.py:297-302`），SSE 看到 `status != running` 就 `return`（`agent_runtime.py:160-161`），前端只能收到流关闭 → 报「事件流断了」。这个必须前后端一起改，前端单独改不了。
4. **输入框的问题不是缺动效，是缺状态机**。它现在只有 `open` 一个布尔（`AiDock.tsx:27-38`），聚焦即开（:402）、遮罩吃首击（:197-209）、Esc 不关、Tab 出文档。动画只是最后一步的糖。

## 2. 目标形态：四条体验主线

1. **空间连续**：任何「进入更深一层」的动作，都能看见它从哪儿长出来、回哪儿去。卡片→详情、缩略图→灯箱、tab 之间、甚至返回列表，都不应该有「换了一页」的空白帧。
2. **生成可见**：AI 在干活时，界面要显示它在干什么、已经产出了什么、能不能中断。没有一个「转圈十几秒然后一次性出现」的块。
3. **手不离键盘**：主流程（筛选、浏览、打开、返回、问 AI、停止、确认）全部可键盘完成，且焦点永远落在可预期的地方。
4. **危险可逆**：破坏性动作要么先问，要么给 5 秒撤销。不允许「点了就没了」。

## 3. 批次 0：先造四个原语（0.5 天，所有后续依赖它）

这四件事不先做，后面每个页面都会再长一套方言——这正是上一轮评审里「设计系统被逐页就近实现侵蚀」的同款病。

### 3.1 `web/src/motion/tokens.ts`

把散落的时长/曲线收成常量，供 JS 与 CSS 共用：

```ts
export const EASE = [0.22, 1, 0.36, 1] as const;      // 已有，统一
export const D = { fast: 0.16, base: 0.24, slow: 0.38, page: 0.42 };
export const SPRING = {
  soft: { type: "spring", stiffness: 320, damping: 34 },
  snappy: { type: "spring", stiffness: 460, damping: 38 },
} as const;
```

CSS 侧同步 `--dur-fast/base/slow` 三个变量（现在 theme.css 里是散写：`0.16s`、`0.24s`、`0.34s` 混用）。

### 3.2 `web/src/motion/nav.ts`（替换 navTransition.ts）

三个必须解决的点：**多命名元素**、**并发不打架**、**按场景分组动画**。

```ts
type NavKind = "push" | "back" | "tab" | "lightbox" | "filter" | "plain";

interface NavOpts {
  names?: Array<{ el: Element | null; name: string }>; // 读阶段挂名，写阶段清掉
  hold?: number;   // 快照前等一帧，避免首帧空
}

let seq = 0;                       // 并发令牌
export function runNav(kind: NavKind, apply: () => void, opts: NavOpts = {}) {...}
```

规则：

- **并发**：每次调用 `++seq` 存进闭包；`finished.finally()` 里只有 `mySeq === seq` 才 cleanup。前一次未结束时**不排队**（排队会让连点变卡），直接 `apply()` 跳过动画，但必须清掉上一次留下的 name 与 root class。
- **分组**：root 加 `vt-push` / `vt-back` / `vt-tab` / `vt-lb`，CSS 里对 `::view-transition-old(root)` 与 new 分别给动作（push：旧页 opacity 1→0 + scale 1→0.985；back：反向；tab：只做 8px 位移 + 淡入）。
- **命名**：只允许 ≤3 个，且必须唯一（`of-media-<id>`、`of-title-<id>`、`of-lb-<index>`）。名字冲突时浏览器会整体降级成根转场——所以工具函数里做一次 `Set` 去重。
- **降级**：`prefers-reduced-motion` 或不支持 `startViewTransition` 时**不跳过交互**，只跳过动画：直接 `apply()`，并在 120ms 内做一个 opacity 交叉（framer-motion 的 `AnimatePresence`，见 4.2）。

### 3.3 `web/src/components/ui/Confirm.tsx` + `useConfirm()`

```ts
const ok = await confirm({
  title: "卸载插件",
  body: "会删掉本地插件目录，之后可从市场重装。",
  confirmText: "卸载",
  tone: "danger",           // 红色按钮
  requireTyping?: "CLEAR",  // 只有清除所有 key 用
});
```

实现要点（这是全站第一个真 dialog，后面 AiDock 也会复用同一套焦点逻辑）：

- portal 到 body，`role="dialog"` + `aria-modal="true"` + `aria-labelledby/aria-describedby`
- 打开时记录 `document.activeElement`，关闭后 `focus()` 还回去
- `Tab` / `Shift+Tab` 在面板内循环（`focus-trap` 手写 20 行足够）
- `Esc` = 取消；初始焦点在「取消」而不是危险按钮
- `tone="danger"` 时确认按钮用 `bg-red` 语义色（暗色下单独一档，不要 `red-600` 直接套）
- 支持 `requireTyping`：输入框必须等于指定词才点亮确认键

### 3.4 `web/src/motion/useHotkeys.ts` + `useAction.ts`

- `useHotkeys(scope, map)`：`scope` 是一个栈（`global / dialog / list / input`），只有栈顶匹配才响应；输入框内（含 IME `compositionstart` 期间）默认吞掉单键快捷键。
- `useAction()`：把一个异步动作包成 `idle | pending | ok | error` 三态，并暴露 `run()` 与`重试`——这是 6.3「开关假成功」和 5.4「断流重试」的公共底座。

## 4. 批次 1：共享元素式转场全站化（1 天）

### 4.1 改「共享什么」：容器 → 内容

现在 `of-card` 命中的是整个 `motion.article`（`Card.tsx:229`），详情侧 `Shell` 是整页容器（`ItemPage.tsx:423-429`）。所以视觉上是「卡片被拉大成页面」，中间那段其实什么都没共享。

改成两个元素：

- 卡片：缩略图/封面块 `data-vt="media"`，标题 `data-vt="title"`（无图的内容只共享标题）
- 详情：媒体容器 `data-vt="media"`，`h1` 外层 `data-vt="title"`

效果差异：媒体框的圆角与宽高连续变形，标题从小字号插值到大字号（View Transition 会做文字快照插值），卡片其余部分（作者、点赞、meta）淡出而不是被拉伸。这是 iOS 的观感来源。

### 4.2 六条转场清单

| # | 场景 | 共享元素 | 时长 | 降级（无 VT） |
|---|---|---|---|---|
| T1 | 卡片 → 详情（push） | media + title | 380ms `EASE` | `AnimatePresence` + `layoutId` 媒体框，其余交叉淡入 240ms |
| T2 | 详情 → 卡片（back） | 同上，反向 | 340ms | 同上反向；落点卡片不在视口则先 `scrollIntoView({block:"center", behavior:"instant"})` |
| T3 | 详情 tab：AI 总结 ↔ 原文 | 媒体区常驻共享 | 200ms | 内容交叉淡入；要求媒体不卸载（见 6.5） |
| T4 | 图库缩略图 → 灯箱 | 缩略图 ↔ 大图 | 260ms | framer-motion `layoutId="of-lb-"+index`，遮罩同步 `opacity 0→1` |
| T5 | 筛选 / 排序变化 | 无（列表 `layout` 重排） | 220ms | `motion.li layout`，仅在 ≤12 项时启用 |
| T6 | 顶栏 → 市场 / 设置 | 无（只做页面级） | 240ms | 淡入 + 8px 上移；**顶栏不参与转场**（加 `view-transition-name: none` 到 `header`） |

为什么 T5/T6 不做共享元素：没有空间连续性，硬做会变成「两个不相干的东西硬飞」，反而更假。**沉浸感来自克制**，不是每个跳转都飞一下。

### 4.3 沉浸式的四个工程前提

1. **预取**：卡片 `onPointerEnter` / `onFocus` 停留 260ms 后，预取 `/api/item/{id}`、detail 首屏、summary 的 `meta`（不含正文生成）。用 `AbortController` 在离开时取消。这样点击时数据大概率已在缓存，转场里不会出现空骨架。
2. **首帧等高**：详情页骨架的高度必须与「媒体 + 标题 + 两行 meta」接近（现在 `ItemPage.tsx:653-669` 是通用骨架，高度和真实内容差得多）。等高是「不跳动」的前提，用户对整页位移最敏感。
3. **转场期间锁滚动**：`html.vt-running { overflow: hidden; }` 配 `scrollbar-gutter: stable` 防止滚动条消失带来的 15px 横移。转场结束立刻解锁。
4. **返回的落点重锚**：现在 `FeedPage.tsx:47-64` 只找一个 rAF，数据回来晚了就放弃。改成「等 `useFeed` 的 `loading` 变 false 再滚一次」，并用 `ResizeObserver` 在首屏图片加载完后再对齐一次（图片撑高会推走卡片）。

### 4.4 卡片必须是链接（顺带修 A1）

T2 的返回手感依赖「浏览器知道这是一次导航」。把卡片换成 `<a href="/item/...">` 后：

- 中键 / ⌘+点击 新标签、右键「在新标签页打开」、拖拽 全部恢复
- `Enter` 是原生行为，删掉 `role="button"` 与 `tabIndex`
- 统一拦截 `onClick`：只拦截「普通左键且无修饰键」，其余交给浏览器

### 4.5 验收

- 卡片 → 详情：肉眼可见媒体框从卡片位置连续长大，标题迁移，中间无白帧
- 连点两张卡片：第二次直接跳转（无动画），不出现 view-transition 卡死
- `prefers-reduced-motion` 打开：所有转场瞬时，功能完整
- Firefox（无 `startViewTransition`）：功能完整，视觉为 240ms 交叉淡入，不报错
- 返回：落点卡片在视口内居中，且图片加载后不再位移

## 5. 批次 2：AI 总结流式（1 天：后端 0.5，前端 0.5）

### 5.1 为什么不能直接给现有接口加 `stream=True`

三个硬约束：

1. `ai.py:144-161` 是 `urllib.urlopen(...).read()` 一次性读，必须改成逐行读 `data:` 帧。
2. 现有 prompt 要求 `response_format: {"type":"json_object"}`（`ai.py:153`）。OpenAI 兼容网关里，"流式 + json_object" 支持度参差，逐字符 JSON 在前端也无法增量渲染（JSON 未闭合）。
3. 前端要的是「先一句话，再逐条要点」，而不是「一个 JSON 慢慢变长」。

### 5.2 协议：服务端流式 + 行式中间格式

**模型侧**改成行协议（不再要 JSON）：

```
TL;DR: 一句话结论，30 字内
- [03:12] 一个要点
- [07:40] 另一个要点
CAVEAT: 可为空
```

**传输侧** SSE，事件类型：

```
event: meta      data: {"basis":"transcript","source_chars":8210,"provider":"MiniMax","model":"..."}
event: tldr      data: {"text":"一句话结论"}
event: point     data: {"t":192,"text":"一个要点"}
event: final     data: {"payload":{...完整 payload，与现有 schema 同构...},"ms":4120}
event: error     data: {"message":"..."}
```

**最终 payload 不变**（`tldr / points[{t,text}] / caveat / basis / basis_text / provider / model / ms / source_chars / note`），所以 `store.save_summary` 与 Agent 侧 `actions.py:_pack_summary` 完全不用改。

### 5.3 后端改动

1. `onefeed/ai.py` 新增 `stream(messages, ...)`
   - 按 provider 顺序试；**首个 token 到达即锁定**该 provider，之后失败不再换（避免两份半截回答拼接）
   - 未产出任何 token 前失败 → 换下一个；全失败 → `raise`
   - `urllib` 逐行 `readline()`，解析 `data: {...}` 与 `[DONE]`，产出 `{"type":"meta"|"delta"|"done"|"error"}`
   - 保留现有 `complete()` 不动（Agent 还在用）
2. `onefeed/summary.py` 新增 `stream_build(store, host, row) -> Iterator[dict]`
   - 先 `yield meta`（basis、素材字数）
   - 增量解析：按 `\n` 切缓冲；`TL;DR:` 行累积（可能跨 chunk）；`- ` 行即一条要点；正则 `^\[(\d{1,2}):(\d{2})\]` 取时间戳
   - 结束 `yield final`，同时构造与现有 schema 一致的 payload
   - 素材不足时走原规则降级（`_rule_summary`），只是改成逐条 yield，UI 一致
3. `onefeed/api.py` 新增 `GET /api/item/{item_id}/summary/stream`
   - 命中缓存 → 直接一帧 `final`（不花 token）
   - `StreamingResponse(..., media_type="text/event-stream")`，headers 带 `Cache-Control: no-cache` 与 `X-Accel-Buffering: no`
   - **partial 暂存**：内存 dict `{item_id: {text, events, at}}` 保 5 分钟，支持 `?after=N` 续流（断网后不重头生成）
   - 同一 item 并发请求：新请求接管，旧生成器在下一次 `yield` 时发现 token 变了就 `return`
   - 旧阻塞端点保留（Agent 的 `actions.py:435-448` 在用）
4. 超时：单次 90s 硬上限；无 token 15s 判定卡死 → `error`

### 5.4 前端改动

新增 `web/src/components/SummaryStream.tsx`（替换 `SummaryPanel` 的 loading 分支）：

- 用 `fetch + ReadableStream` 手解 SSE（不用 EventSource：要 `AbortController`，也要带 `refresh` 参数）
- **合帧**：delta 先进 buffer，`requestAnimationFrame` 每帧最多 setState 一次，避免长文把 React 打满
- 渲染序列：
  1. 骨架（固定高度，防跳动）
  2. `meta` 到达 → 顶部出现「依据：完整字幕 · 8210 字」
  3. `tldr` 逐字出现，尾部一个 12ms 脉冲光标
  4. 每条 `point` 进入时 `motion.li` 8px 上移 + 淡入，间隔 60ms
  5. `final` → 淡入「重新总结 · 去原站 · MiniMax · 4.1s」，光标消失
- 断流：保留已收到的 tldr/points，底部出现「继续生成 · 从头重来」两个入口；`?after=` 续传时不要把已有内容清空
- 失败（无 token）：退回现有规则摘要（`_rule_summary`），并标注「未接入模型，按素材顺序摘录」

### 5.5 验收

- 首字延迟 < 1.5s（本机模型），整条 3–8s 内完成
- 生成中滚动页面不抖：骨架高度 = 最终内容高度的 ±10%
- 中途断网：已生成内容保留，可续传
- 同一 item 第二次打开：缓存命中 < 50ms，直接整块出现（无打字机动画）
- 关掉所有 key：走规则摘要，页面文案明确说明

## 6. 批次 3：输入框动效 + AI 面板键盘模型（0.5 天）

### 6.1 输入框（composer）的三段动效

| 状态 | 视觉 | 实现 |
|---|---|---|
| 收起（药丸） | 高 48px，圆角 24，hint 文案「问我一句话，或直接说条件」 | 现状 |
| 聚焦展开 | 圆角 24→16，高度到 `62vh`，面板从底部 12px + 淡入 | `motion.div layout` + `animate={{ borderRadius }}`；面板 `AnimatePresence` 8px 上移 |
| 生成中 | 输入框底部一条 2px 进度扫光；发送键变停止键（同一位置，图标 swap） | `AnimatePresence mode="popLayout"` 跨 120ms |

细节：

- 不要 `onFocus` 就展开（这是 A2 的病因）。改 `onClick` 与 `⌘K` 展开；聚焦但不输入时保持药丸。
- 占位文案轮播（3 条示例，4s 换一次，`AnimatePresence` 6px 交叉）——比静态 placeholder 更能教用户怎么说。
- 发送键三态：`disabled`（灰、无光标）→ `ready`（实心）→ `sending`（三点脉冲，且整键可点=停止）。
- 面板打开时**不要全屏遮罩**：改为 `pointer-events-none` 的视觉暗角（`bg-solid/5`），或干脆不做。点面板外关闭用 document 级 `pointerdown` 判断 `contains`。

### 6.2 键盘模型

**全局**（`useHotkeys("global")`）：

| 键 | 行为 |
|---|---|
| `/` 或 `⌘K` / `Ctrl+K` | 打开并聚焦 AI 输入框 |
| `Esc` | 依次关闭：dialog → 灯箱 → AI 面板 → 清空搜索/筛选 |
| `?` | 打开快捷键帮助（dialog） |
| `t` | 切换主题（已有按钮，补快捷键） |
| `r` | 刷新一轮（避开输入框聚焦时） |

**列表**（`scope="list"`，roving tabindex）：

- `j` / `k`：焦点上/下一张卡片（`scrollIntoView block:"nearest"`）
- `h` / `l`：跨列（`md` 以上）
- `Enter`：打开（原生 `<a>` 行为）
- `o`：新标签打开
- `s`：收藏/取消
- `g` 然后 `h`：回首页（可选，vimer 彩蛋）

**胶囊**（改造 `TabRail.tsx:470-479`）：

- `←/→`：**只移动焦点，不改筛选**（现状是直接 `choose()`，实测把 `?p=bilibili` 按成 `?p=douyin`）
- `Enter` / `Space`：应用当前焦点项
- `Home` / `End`：首/末
- `Esc`：回到「全部」
- 多选仍然 `⌘/Ctrl+点击`，但额外给一个可见的「多选」开关（开启后胶囊变 `role="checkbox"` + `aria-checked`），把隐藏手势变成可发现能力

**焦点可见性**：统一 `focus-visible` 环（2px `ring-ink/25` + 2px offset），且只在 `:focus-visible` 出现，鼠标点击不出现。键盘用户从顶部 Tab 进入时，第一个元素应该是「跳到内容」的 skip link（现在没有）。

### 6.3 面板本身（顺带给 AiDock 做 dialog 化）

- `role="dialog"` `aria-modal="true"`，打开记 `activeElement`，关闭归还
- `Esc` 关闭（现在完全没接）
- `Tab` 循环；DOM 顺序改成 composer 在前、面板在后（视觉可仍在上方，用 `flex-col-reverse` 或 portal 分层）

## 7. 批次 4：停止按钮（0.5 天：后端 0.3，前端 0.2）

### 7.1 后端：让取消真的停

1. **检查点**（`onefeed/agent_runtime.py`）：
   - 循环每步开始前 `if state.cancel: raise Cancelled`
   - 每次工具调用**前后**各一次
   - 工具之间用 `state.cancel_event.wait(timeout)` 替代 `time.sleep`，收到取消立刻醒
2. **工具内**：`actions.py` 的 dispatch 包一层 `_guard(deps, fn)`，进入前检查；网络类工具本来就带 timeout，返回后**丢弃结果**（不写库、不发 `action` 事件）
3. **事件**：取消时写 `done` 事件 `{"status":"cancelled","reason":"user"}`，再 `finish_agent_run(...,"cancelled")`；`sse_stream` 在 `status != running` 时**先 flush 剩余事件再关闭**（现在的 :160-161 直接 `return`，前端分不清「完成」和「取消」）
4. **接口语义**：`POST /cancel` 只置位并返回 `{"ok":true,"cancel_requested":true}`，**不再自己 finish**（避免双写、避免事件丢失）
5. **兜底**：5s 未停 → 状态 `stopping`；工具超时（现有 30s 级）后强制 `finish` 并标注「工具未返回，已强制结束」

### 7.2 前端：三态

```ts
type RunState = "idle" | "running" | "stopping" | "cancelled" | "error";
```

- 点停止 → `stopping`：按钮文案「正在停止…」，输入框禁用，仍可关闭面板
- 3s 未收到 `done` → 黄色提示条「停止请求已发出，工具返回后会立即结束」（不要假装已停）
- 收到 `done{status:"cancelled"}` → 该轮标记「已取消」，右侧给「重发这条」按钮；`busy=false`
- 断流（onerror）→ 不再报「事件流断了」，改为「连接中断 · 重连」（重连用 `?after=lastSeq`）
- 取消后**保留已发生的动作记录**（轨迹里已执行的写操作要能撤销，`undo_token` 已有）

### 7.3 测试

`tests/test_agent_cancel.py`：

- 假工具 sleep 2s；发出 cancel 后 300ms 内断言下一次工具未执行
- 事件流按序含 `run_start → step → done(cancelled)`
- run 状态为 `cancelled`，且**没有**后续 `action` 事件
- 无 cancel 时行为不变（回归）

## 11. 风险与取舍

| 风险 | 影响 | 对策 |
|---|---|---|
| View Transition 快照成本 | 大图或长页会掉帧 | 只命名媒体框 + 标题两个元素；单帧快照 < 2MB；不命名整页容器 |
| Firefox 无 `startViewTransition` | 一半用户看不到共享元素 | framer-motion `layoutId` 降级；功能不依赖动画 |
| 流式 + 部分网关不支持 | 生成失败 | 先探测（`stream:true` 试一帧），失败回落阻塞端点 + 规则摘要 |
| 取消无法打断阻塞 IO | 停止有延迟 | 工具级超时 + 返回后丢弃结果；UI 明确显示「将在工具返回后停止」 |
| framer-motion `layout` 长列表掉帧 | 滚动卡 | 仅 ≤12 项启用 layout；其余用 CSS transition |
| 打字机效果干扰阅读 | 用户反感 | 只在首字后 2s 内启用；用户滚动或失焦立即整段呈现；缓存命中不播 |
