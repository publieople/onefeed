## 逐页口播

### 封面（0:00–0:15）

评委老师好，我们是 Undefined。OneFeed 想解决一件很小、但每天都会发生的事：把七个平台的信息流，收进同一屏。

### 01 问题（0:15–1:00）

现在看信息是碎的。B 站、抖音、小红书、知乎、热榜、掘金、V2EX，七个 App，七套交互。想比较同一件事，要来回跳；视频、图文、问答、榜单，收藏和搜索互不相通；平台自带的总结只覆盖单条，不能按自己的条件跨平台找。我们统计了一下，同样一个话题，最多有七个平台在讲。

### 02 方案（1:00–1:50）

OneFeed 的做法是三层。第一层，统一卡片：平台、作者、时间、互动数、封面统一呈现，视频、图文、问答、动态、榜单共用一套详情页。第二层，插件采集：每个平台一个插件，manifest 声明能力，插件市场负责安装、更新、卸载。第三层，AI 和关注流：详情页有三档总结，可以继续追问；Agent 能理解跨平台条件，库里没有会主动去抓；关注流把 B 站 602 个关注账号的动态聚在一起。所有数据落在本机 SQLite，不经过我们的服务器。

### 03 现场演示（1:50–3:00）

现场看三件事。第一，七个平台在同一屏，左边是筛选，中间是卡片，右边是 Agent 工作台。第二，点开一条 V2EX，AI 总结三档，右栏直接问“这条讲了什么”，回答完过程自动折叠成四步，只留结果。第三，滑到底部，只检查当前筛选的平台，有新内容就并进首屏，滚动位置不动。刷新时顶栏从按钮左侧长出进度胶囊，结束自动收起，不占信息流一行。

### 04 技术（3:00–4:00）

技术上，我们不是套一个壳。后端 Python、FastAPI、SQLite；前端 React、TypeScript、Vite；插件跑在 QuickJS 子进程沙箱里，需要浏览器的平台走 Playwright；登录态由宿主注入，插件不保存密码。AI 走 OpenAI 兼容接口，MiniMax 优先、DeepSeek 兜底，Key 在本机，可以关。现在七个插件在线，32 组验收脚本全过，CI 绿；Pages 有 84 条静态快照，仓库里有 63 条离线快照，断网也能演示。

### 05 边界与团队（4:00–5:00）

边界我们提前说清楚：只读，不发布、不点赞、不评论；登录态不内置；采集有平台冷却；插件失效会显式提示，不影响其他平台。团队三个人：周铉产品与视觉，冯周杰后端与插件，杨健豪前端与测试。下一步想把关注流扩到更多平台，把跨平台对照做成默认视图。最后一句话：把七个平台，收进一屏。谢谢。

## 可能被问到

**Q：和 Folo、Follow、RSS 阅读器有什么区别？**
A：它们以订阅源为中心，OneFeed 以“跨平台比较一件事”为中心：同一话题的多平台卡片、统一详情、按条件让 Agent 去补抓，以及把采集过程做成可见的进度和失败提示。数据默认在本机，不经过我们的服务器。

**Q：插件会不会违反平台条款？**
A：只读采集，不发布、不点赞、不评论；登录态由宿主浏览器注入，插件不保存密码；采集有平台级冷却，避免高频请求。平台条款或页面结构变化导致插件失效时，会显式提示，不影响其他平台。

**Q：AI 总结会不会编？**
A：总结只基于已抓到的正文、字幕或图片，素材不足时会明确写“素材不足，无法形成结论”；模型顺序可配置，也可以完全关闭，只留规则解析。

**Q：为什么不做云端 SaaS？**
A：个人内容台最敏感的是登录态和数据去向。本地优先让用户看得见数据落在哪、模型 Key 存在哪；代价是首次配置比 SaaS 重，我们用插件市场和离线快照降低门槛。

**Q：商业化怎么办？**
A：先不急着收费。插件市场可以承载平台适配和团队版同步；当前阶段优先把七平台覆盖、采集稳定性和跨平台对照做扎实。
