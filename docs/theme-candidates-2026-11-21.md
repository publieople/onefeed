# OneFeed 换主题：uupm.cc 风格库调研与四套候选

日期 2026-11-21。目的：给 OneFeed 换一套设计主题，先出可选方案与推荐，不动代码。
配套预览：`design/theme-preview.html`，截图 [2026-11-21-theme-candidates.png](images/2026-11-21-theme-candidates.png)（同一份真实内容渲染 5 屏：四个候选 + 推荐方案的夜间版）。

---

## 一、uupm.cc 是什么，能查到什么

uupm.cc 是 **UI/UX Pro Max**（NextLevelBuilder），一个把设计决策写成数据的知识库：

| 数据 | 规模 | 文件 |
| --- | --- | --- |
| UI 风格 | 88 条（active 50 / supplemental 29 / deprecated 9） | `styles.csv` |
| 产品类型规则 | 194 条 | `ui-reasoning.csv` |
| 产品色板 | 194 组 | `colors.csv` |
| 字体搭配 | 74 组 | `typography.csv` |
| 图表类型 | 25 | `charts.csv` |
| 技术栈落地 | 22 | `stacks/*.csv` |

官网是 Next.js 单页应用，直接抓 HTML 拿不到条目；我把 CLI 包解到本地再读 CSV（`.onefeed/tmp/uupm/package/assets/data/`），按 `Style Category`、`Best For`、`Do Not Use For`、`ui-reasoning` 的 `Anti_Patterns` 三列筛。字段里有引号内逗号和换行，读的时候要按 CSV 规范解析，不能按逗号切。

**它对「这类产品该用什么」给的是规则而不是偏好**，例如：

- `News/Media Platform` → 风格优先「Minimalism & Swiss Style + Flat Design」，色彩「品牌色 + 高对比」，反模式「杂乱布局 / 慢加载」。
- `Magazine/Blog` → 风格优先「Swiss Modernism 2.0 + Motion-Driven」，字体气质「编辑感 + 优雅」，反模式「排版差 / 慢加载」。
- `Bookmark & Read-Later` → 「极简瑞士 + 扁平」，色彩「暖白纸 + 墨中性色 + 极小面积强调色 + 标签色」，关键效果「hover 变色 + 150ms 过渡 + 无阴影」，反模式「过度装饰 / 复杂阴影 / 3D」。

OneFeed 横跨这三类：信息流（News/Media）、长期阅读与 AI 摘要（Magazine/Blog）、稍后再看与收藏夹（Read-Later）。所以下面四套候选全部落在这三条规则的邻域里，没有选 Bauhaus、Gradient、Glassmorphism 这类和「读」相冲突的方向。

## 二、四套候选

四套共用同一套页面骨架，只换设计语言。具体色值、圆角、字体都写进了预览页的 CSS 变量，可以直接抄。

### T1 · 纸上（E-Ink / Paper + Editorial Grid）——推荐

| 项 | 值 |
| --- | --- |
| 纸 | `#FDFBF7`，卡片 `#FFFEFB` |
| 墨 / 次级 / 弱 | `#1A1A1A` / `#57534B` / `#8B8578` |
| 线 / 洗 | `#E6E0D4` / `#F4EFE4` |
| 强调 | `#B45309`（琥珀，只给星标、当前项、链接） |
| 圆角 | 外壳 6px、卡片 4px、徽标 3px、胶囊 999px |
| 阴影 | 无，只留 `0 1px 0 rgba(26,26,26,.04)` |
| 标题字体 | Noto Serif SC 600 |
| 正文字体 | Noto Sans SC（保持现状） |
| 夜间 | 纸 `#14120F`、卡 `#1A1815`、墨 `#ECE7DC`、强调 `#E0A45C` |

**为什么推荐**：这是唯一一套「换掉气质但不换骨架」的方案。现在的 OneFeed 是一张白纸配灰线，改为暖白纸之后，卡片、胶囊、发丝线、等高网格全部不动，改造成本集中在变量层。宋体标题给「读」的感觉，正文仍是黑体，中文小字号不会发虚。

**代价**：需要给 `theme.css` 加一个强调色变量（现在没有），并把 `borderRadius.card: 12px` 降下来；宋体只用在 ≥14.5px 的标题上，14px 以下仍走黑体。

### T2 · 瑞士网格（Swiss Modernism 2.0）

| 项 | 值 |
| --- | --- |
| 底 / 卡 | `#FBFBF9` / `#FFFFFF` |
| 墨 / 次级 | `#0E0E0E` / `#55585C` |
| 线 / 洗 | `#DEDFD9` / `#F1F1EC` |
| 强调 | `#E2401F`（朱红，全站唯一彩色） |
| 圆角 | 0–2px |
| 阴影 | 无，靠 1px 发丝线和数字对齐建立秩序 |
| 字体 | 全站 Noto Sans SC，标题 700 + 负字距 |

**为什么列进来**：最安全的一套，几乎是「把现在的东西收干净」。风险最低，气质偏工具、偏文档。
**代价**：和现状差别最小，用户可能感觉不到「换了主题」；零圆角会让胶囊筛选、AI 输入条失去现在的柔和感。

### T3 · 黑白编辑（Minimalist Monochrome）

| 项 | 值 |
| --- | --- |
| 底 / 墨 | `#FFFFFF` / `#000000` |
| 洗 | `#F5F5F5` |
| 线 | `#000000`（卡片 1px、外壳与页脚 2px） |
| 强调 | 无强调色，**七个平台色成为全页唯一彩色** |
| 圆角 | 0 |
| 字体 | 标题 Noto Serif SC 700，正文 Noto Sans SC |

**为什么列进来**：辨识度最高。聚合器的本质是「把不同来源放进同一个容器」，让平台色成为唯一彩色在语义上很准。
**代价**：要重做边框体系（现在全是浅灰 1px），黑白对比会让「已读/未读」「选中/未选」缺少中间层次；长文阅读时纯白偏刺眼。建议只借用它「平台色是唯一彩色」这条规则，不整套换。

### T4 · 暖墨（Bookmark & Read-Later 色板）

| 项 | 值 |
| --- | --- |
| 纸 / 卡 | `#FFF8E6` / `#FFFFFF` |
| 墨 | `#0F172A` |
| 线 / 洗 | `#F2E2C6` / `#FDF1D8` |
| 强调 | `#B45309` |
| 圆角 | 外壳 10px、卡片 10px、胶囊 999px |
| 阴影 | `0 1px 2px rgba(24,16,8,.05)` |

**为什么列进来**：最亲和，像「我的收藏册」，和稍后再看、收藏夹的定位一致。
**代价**：琥珀底 + 大圆角会削弱「严肃聚合器」的可信度；和 T1 定位重叠，两者只能选一。

## 三、推荐

1. **T1 纸上**——首选。它只改表面、不改布局，风险最低，同时是四套里唯一给「读」的气质加了分贝的。夜间版用暖黑纸（`#14120F`）而不是纯黑，长时间看长文更稳。
2. **T2 瑞士网格**——备选。如果目标其实是「收干净、更像工具」，选它。
3. **T3 黑白编辑**——只借规则，不整套换。
4. **T4 暖墨**——暂不推荐，与 T1 重叠且会拖低可信度。

如果只能做一件事：把 T1 的色调、圆角、宋体标题落下，**平台色、等高网格、转场、滚动缓动一律不动**。

## 四、落到现有代码

现有 token 在 `web/src/theme.css:6-21`（亮）与 `:24-39`（暗），全部是 `R G B` 三元组，由 `tailwind.config.js` 映射成 `ink/muted/paper/line/wash/solid`。T1 的映射：

| 变量 | 现在（亮） | T1（亮） | T1（暗） |
| --- | --- | --- | --- |
| `--c-paper` | 255 255 255 | 253 251 247 | 20 18 15 |
| `--c-wash` | 247 248 249 | 244 239 228 | 31 29 25 |
| `--c-line` | 233 234 236 | 230 224 212 | 44 42 37 |
| `--c-ink` | 20 22 26 | 26 26 26 | 236 231 220 |
| `--c-muted` | 107 114 128 | 87 83 75 | 179 171 157 |
| `--c-fade` | 154 161 171 | 139 133 120 | 133 126 114 |
| `--c-solid` | 20 22 26 | 28 28 28 | 236 231 220 |
| `--c-accent`（新） | 无 | 180 83 9 | 224 164 92 |

配套三处：

- `web/tailwind.config.js:23` `borderRadius.card: "12px"` → `4px`；新增 `accent` 颜色映射。
- `web/src/theme.css:47-55` 与 `tailwind.config.js:20-22`：新增 `fontFamily.display = ["Noto Serif SC", "Songti SC", serif]`，只给 h1/h2/卡片标题用。
- 字体不需要下载：本机 `C:\Windows\Fonts` 已有 `NotoSerifSC-VF.ttf` 与 `NotoSansSC-VF.ttf`，Windows/macOS 上直接用系统字体名即可；若要跨 Linux 一致，再考虑自托管 woff2（两个子集约 300–400KB，会进首屏关键路径，建议先不做）。

**切换方式**建议用 `data-theme`：`:root` 放默认（T1 亮），`html[data-theme="paper-dark"]` 覆盖暗色，而不是把变量写死在 `html.dark` 里——这样以后想加第二套主题不用重写。现有的换肤是对角 View Transition（`theme-vt`），换 token 不影响它。

**验收**：`pwsh scripts/preflight.ps1`（pytest / run_all / check-ui / build）全绿；再用 `probes/` 里的对比度检查重算一遍 `text-muted`、`text-fade` 与 `underline`——T1 把 muted 从 `#6B7280` 压到 `#57534B`，对比度反而上升，但 fade 在暖白纸上的观感要实测。

## 五、风险与不做的事

- **不做**「一屏一套主题」的选择器。先落一套，暗色跟随。多主题会让每个组件的状态都要乘一遍，测试成本翻倍。
- **不改**平台色。四套候选里平台色一律保留，它们是信息而不是装饰。
- **不改**动效。uupm 对 E-Ink 的建议是「sharp transitions (no fade)」，与我们已做的宽度补间、滚动缓动冲突；这条不采纳——动效是上一轮专门调过的，主题只管表面。
- 宋体在 12–13px 的 Windows ClearType 下会偏细，标题强制 ≥14.5px，卡片标题现在是 14.5px，正好卡在线上，落地时要在 125% 缩放下复核一次。
- 若最终选 T3，必须先解决「已读/未读」「选中/未选」的中间层次，否则黑白两色撑不住三层状态。
