## 二、必须解决的问题

### P0（不做会影响现场演示或报名）

1. **默认端口被别的项目占用**。→ ✅ 已改（当日晚）：启动时探测端口，被占则自动往后找 10 个，日志写「端口 8787 被占用（PID …），自动改用 8788」；实测 8787 被 openmontage 占用（PID 48160）时自动跑在 8788，若占着的是另一个 OneFeed 就直接开浏览器复用。
2. **没有扫码登录闭环（T43）**。→ ✅ 已做（当日晚）：设置页「打开登录窗口」→ 宿主用 Playwright 持久上下文起一个独立 Chrome → 每 2 秒轮询 cookie → 命中登录 cookie 就落盘并自动关窗；「退出」删 cookie 与 profile。实测抖音：窗口 3.7s 起来、cookie 0 → 22、状态 waiting → 关闭；HTTP 链路 `need_login → login → waiting → logout → need_login` 全通。**尚未验证**：真人在窗口里扫一次码的 ok 分支（代码路径由单测覆盖）。
3. **登录态判定与数据自相矛盾**。→ ✅ 已改（当日晚）：抖音的 impact 文案写明「未登录也能采到网页推荐流；登录后是更贴近你自己的那一条」；窗口开着时 `/api/auth` 返回窗口态、不再重复静态提示。
4. **没有演示清单与录屏（T50/T51）**。没有 `docs/DEMO_CHECKLIST.md`，没有 3 分钟兜底视频，也没按现场流程完整走过两遍。`--demo` 可用，但没人验证过「断网 + 空库 + 装插件 + 拉详情」全链路。
5. **报名材料不齐（11-18 截止）**。报名表缺队名、微信号、两名队员（姓名/学院/专业/年级/分工）；demo 打包 zip 没做；邮件没发（2022874341@qq.com，命名「团队名+队长姓名」）；训练营三场的时间地点仍未知。

### P1（体验和答辩上的硬伤）

6. **详情抽屉没有评论区**。→ ✅ 已做（当日晚）：评论区做成插件的可选能力（`plugin.json` 的 `features: ["comments"]` + `comments(item, opts)`）。B 站插件 0.2.0 已实现，抽屉实测拉到 20 条真实评论（含楼中楼 3 层内）；没声明的平台明确写「这个平台的插件没有提供评论接口」，不转圈、不报错。
7. **统计标签不分场景**。→ ✅ 已做：抽屉按 kind 选标签（video 播放 / article 阅读 / images·short 浏览 / list 热度），缺的整块隐藏、不显示 0。
8. **收藏是死按钮**。→ ✅ 已换掉：抽屉里改成「复制链接」（失败回退 execCommand），不再有假按钮。
9. **市场没有更新与版本对比**。→ ✅ 已做（当晚）：registry 版本比已装新才提示（`cmp_version`），卡片显示 `v0.1.0 → v0.2.0` + 「更新」按钮，顶栏「全部更新 (N)」；更新保留用户关掉的开关；另加自动更新开关（默认关）。
10. **没有设置 API（T44）**。→ ✅ 已做（当日晚）：`GET/PUT /api/settings` + 设置页表单（插件目录、registry、每平台每轮条数、评论条数、默认排序、保留天数），保存后采集进度即时生效；env 覆盖的键不落盘。
11. **热度排序把榜单和论坛帖压到底**。→ ✅ 已改（当晚，T46）：按平台内 `PERCENT_RANK` 归一成 0–1000 的 `engage_score`（平台内全为 0 就记 0，免得并列满分），排序与「B 站同类里前 28%」这类理由都改用它；实测热度榜首榜覆盖全部六个平台。
12. **缺封面时视觉像 bug**。→ ✅ 已改（当晚）：没有封面显示虚线占位块 + kind 图标 +「无封面 · 平台名」，图片加载失败也落到占位块。

### P2（工程债，现场可能咬人）

13. **一轮采集 ~90 秒**（B 站 30s+，两个浏览器插件各 15s）。演示前必须先 `--warmup`，否则现场等刷新条。
14. **一个实例有两个 python 进程**（venv launcher + 真实解释器）。按端口提示的 PID 杀进程可能只杀到外壳，残留子进程继续占端口。
15. **fixtures 停在 11-14 23:30**。`--demo` 展示的是那天的数据，演示前要重新 `--warmup` 导出。
16. **没有 CI**。→ ✅ 已加（当晚）：`.github/workflows/ci.yml`，python job（3.12 + `uv sync --frozen` + `tests/run_all.py --offline`）与 web job（node 20 + `npm ci` + `npm run build`）。
17. **插件目录依赖同级 `../onefeed-plugins/plugins`**。换机器要用 `ONEFEED_PLUGINS`，README 有写，但没做成默认自动发现。
18. **依赖系统 Chrome + Playwright**（`channel="chrome"`）。Chrome 大版本升级可能让 browser 能力失效，没有版本检查或降级提示。
19. **数据库没有自动 checkpoint/prune**。`prune()` 只在采集结束时调用，长期开着会累积。
20. **合规口径还没落成文案**。只读、不下载、不代发、不破解签名、插件作者行为与宿主无关——这几句要在 deck 和 README 里固定下来，评委必问。

## 五、当晚补齐（2026-11-15 21:00）

### 插件市场：更新 / 全部更新 / 自动更新

- 后端：`market.cmp_version / update / update_all / pending_updates`；`POST /api/plugins/{id}/update`、`POST /api/market/update-all`、`GET /api/market/updates`。
- 设置：`auto_update`（默认 **关**——现场演示不让远端静默换插件）。开着一轮采集前先 `update_all()`，结果写进 `/api/progress` 的 `market` 字段；单个插件失败只记原因，不中断采集。
- 前端：市场页 `v0.1.0 → v0.2.0` + 「可更新」徽章 + 「更新」按钮 + 顶部「全部更新 (N)」；已停用的插件更新后仍是停用。
- 真实链路验过：库里把 bilibili 版本改回 0.1.0 → `/api/market/updates` 报 1 条 → UI 点「更新」→ 走 GitHub/jsDelivr 下载 + sha256 校验 → 0.2.0 落盘，`updates` 归零。

### 顺手修掉的三个 bug（都会咬演示）

1. **`OperationalError: unable to open database file`（刷新一轮六个平台全挂）**。根因：热度分位用了窗口函数，SQLite 要临时空间，而这台机器的用户 Temp 目录不可写 → 刷新线程写库直接失败（主线程读没事，所以一开始看不出来）。修法：连接上固定 `PRAGMA temp_store=MEMORY`。
2. **插件下载缓存按插件 id 存**。registry 一升级就会命中上一版的旧包，sha256 永远对不上、更新永久失败。改成按「插件 + 期望 sha」分目录，成功后清掉旧版本缓存；新增回归测试（装 1.0.0 → 远端升 1.1.0 → 更新成功）。
3. **刷新失败只剩一句 `OperationalError: ...`**。现在错误里带最后三行 traceback，下次出问题能直接看语句。
