# 收藏夹与「稍后再看」：两件事

日期：2026-11-20

它们都挂星形图标，但在产品里是两个动作：

| | 稍后再看 | 收藏夹 |
|---|---|---|
| 在哪点 | 卡片右下角的星 | 详情页底部「收藏」 |
| 要不要写东西 | 不用，一键进出 | **必须写一句备注**（为什么留） |
| 存哪 | item_marks.saved / saved_at | 独立表 item_favorites |
| 排序 | 加入时间倒序（同一张表里的时间） | 收藏时间倒序（created_at 不随改备注刷新） |
| 移出 | 列表里点星，立即移出并可撤销 5s | 详情页里移出，**先过确认框** |
| 谁会读它 | 信息流「稍后再看」页、卡片状态 | 右栏「收藏夹」页、左栏计数 |

## 为什么不用一张表

共表意味着「note 为空 = 稍后再看」，但收藏夹的备注是必填、稍后再看永远没有备注，
两者只能靠外键标记区分，排序与计数也会互相污染：把一条从稍后再看移出时，
会连带把收藏夹里的备注和顺序一起带走。所以直接分表：

- `item_marks`：saved / read / hidden，卡片一键位。
- `item_favorites`：item_id / note / created_at / updated_at，详情页的长期留档。

schema 版本 7，迁移里 `if version < 7` 建表 + 建索引。

## 接口

- `GET /api/favorites?limit=` → { items, count }
- `GET /api/favorites/{id}` → 单条状态
- `PUT /api/favorites/{id}` body { note }；备注去空白为空 → 400 `need_note`；条目不存在 → 404
- `DELETE /api/favorites/{id}` → { ok, removed }

列表 SQL 必须带 `LEFT JOIN item_marks`：`favorite_items()` 复用 `_decode_row`，
它要读 `m.saved`，少这个 join 会直接 `no such column: m.saved`。

## 交互细节

- 详情页底部「收藏」按钮 aria-pressed，开着的时候显示实心星 +「已收藏」。
- 对话框：强制备注（最多 200 字）、⌘/Ctrl+Enter 保存、Esc 关闭、Tab 在框内循环、
  打开锁滚动、关闭把焦点还给「收藏」按钮。已收藏时同一个框变「编辑收藏」，
  底部多一个「移出收藏夹」，点击再过一次 Confirm（红按钮、说明备注会一起删、
  稍后再看不受影响）。
- 右栏页签：稍后再看 / 收藏夹 / AI 总结 / AI 助手 四个图标位，只有当前页显示文字
  （320 宽放不下四个全名，全显示会把「稍后再看」压成竖排）。
- 左栏：完整形态在「稍后再看」下面多一行「收藏夹 N」，图标轨里多一个心形按钮。
- 点击左栏入口时右栏是关着的，事件先于挂载到达；外壳记住要开哪一页，
  把它作为 RightRail 的 defaultTab，栏挂载时直接落在「收藏夹」。

## 验证

- `tests/test_favorites.py`：两套标记互不影响、重复收藏不刷新 created_at、
  列表带 favorite_note、空备注 400、不存在条目 404。
- `tests/test_side_rails.py` 新增两条：外壳接住 onefeed:rail 并真的开栏；
  收藏夹与稍后再看的数据/接口/交互各自独立（防以后又合并）。
- 真机（Chrome 1440×900）：详情页收藏 → toast「已收进收藏夹」→ 按钮变「已收藏」→
  左栏计数 1 → 右栏收藏夹出现备注行 → 再点开预填备注 → 移出 → 确认框 → 按钮回「收藏」→
  右栏空态。信息流页点左栏「稍后再看 / 收藏夹 / AI 总结」三个入口都能开栏并落在对应页。
