## 1. P0 · 三个会让用户「看不懂」的问题

### P0-1 首屏控制区语义塌陷：三个同权黑胶囊，一个复读标题

**证据**（1440×900，`design/review/feed-1440-light.png`；源码 `web/src/pages/FeedPage.tsx:79-103`）

- 一行里并排三个**同样的实底黑胶囊**：`全部`（时间范围）、`按新鲜度`（排序）、`全部 639`（平台筛选）。三者分属三个不同维度，视觉权重完全相同，且**没有任何分组标签**。
- `h1` 不是页面标题，而是筛选状态的复读：`FeedPage.tsx:80` 的 `{active ? "筛选结果" : range === "today" ? "今天" : "全部内容"}` —— 15px，比卡片标题（16px semibold）还小。
- 同一个数字重复播报：首屏「639」出现 **4 次**（顶栏、筛选行右、平台胶囊、摘要句），「全部」出现 **9 次**。
- 首屏被控制区吃掉 **24.6%**（卡片从 y=221 开始）；390 下是 **34.7%**（y=293 / 844）。

**为什么是问题**：用户打开聚合器要回答三件事——「这是哪」「现在是什么视图」「我怎么换视图」。现在标题答案是「全部内容」（= 状态），三个胶囊长得一模一样（= 分不清维度），数字被念四遍（= 噪音）。这不只是丑，是**信息架构没有层级**。

**修法方向**：一个稳定页面标题（如「今日信息流」）+ 控制区分组（时间 / 排序 / 平台各有 caption 或分隔），把「当前筛选」收敛成一句可清除的描述；全局数字只保留一处。

---

### P0-2 对比度：首屏 84 个文字节点低于 AA，且恰好是元信息

**实测**（`probes/review_contrast.py`，真实 DOM 取色）

| 前景 / 背景 | 比值 | 达标 | 出现位置 |
| --- | --- | --- | --- |
| `--c-fade` #9AA1AB / 白 | **2.61:1** | ✗（AA 4.5） | feed 首屏 32 处（11px 23 / 12px 9）：时间、条数、来源、卡片角标 |
| 知乎 #0084FF 上的白字 | **3.66:1** | ✗ | 平台徽章 11px/500 |
| B 站 #00A1D6 上的白字 | **2.97:1** | ✗ | 同上 |
| 小红书 #FF2442 上的白字 | **3.76:1** | ✗ | 同上 |
| 抖音 #FE2C55 上的白字 | **3.68:1** | ✗ | 同上 |
| V2EX #778087 上的白字 | **4.02:1** | ✗ | 同上 |
| `--c-fade` 落在平台浅底上 | **2.28–2.33:1** | ✗ | 「文字动态」「没有配图」角标 |
| 白 90% 落在榜单渐变上 | **1.06:1** | ✗ | 热榜排名数字 |

- 首屏可见范围内不达标的文字：fade 色 **75 处**（feed 32 / settings 17 / market 26）+ feed 平台徽章 **8 处**，合计 **83 处**。
- 讽刺的是，2.61:1 的 fade 恰好承载「几点发的、哪个平台、多少条」——**读者用来判断要不要点开的信息，正好是最看不清的信息**。
- 暗色下卡片描边 `--c-line` #2C3038 对 paper #0F1115 仅 **1.5:1**，卡片边界在暗色里近乎消失（`design/review/feed-1440-dark.png`）。

**为什么是问题**：这不是「淡雅」的审美选择，是元信息不可读；投屏、打印、低亮度屏直接损失全部上下文。平台徽章**全部**不达标，说明「品牌色做底 + 白字」这个模式本身不成立。

**修法方向**：新建一档 `--c-meta`（目标 ≥4.5，建议 #6B7280 起步并实测）；平台徽章改为「浅底 + 品牌色文字」，或只为徽章加深品牌色 ≥30%；暗色描边提到 ≥2.5:1。

### P0-3 移动端是「缩小的桌面」：控制区吃掉 1/3 屏，胶囊条藏了 394px 还不告诉人

**实测**（390×844，`design/review/feed-390-light.png`）

- 卡片从 y=293 才开始，**首屏 34.7% 是控制区**；摘要自检句占 3 行。
- 平台胶囊条：外层宽 342px，内层 `scrollWidth 726 / clientWidth 332` → **394px 内容被藏**，无渐隐、无箭头、无滚动条（`probes/review_rail.py`）。用户会以为平台只有 4 个。
- 触控尺寸：390 下 **19/50** 个可聚焦元素 < 44px——顶栏 4 个 36px 图标、Seg 高 26px、平台 chip 高 25px、AI 发送键 32px、「加载更多」37.5px。
- 筛选行右侧「7 个平台 · 最近采集 23:08」在 390 被挤成**单独一行右对齐的孤儿**（12px fade，2.61:1）。
- 设置页 390：左导航 `hidden lg:block` **没有任何移动端替代**，五个 section 全部展开成一条长滚动；`27/32` 个可聚焦元素 < 44px，模型名输入实测 **31.3px 宽**（显示成「Mi」），上移/下移/删除三个图标 **21px**。
- 市场页 390：**19/19** 个可聚焦元素全部 < 44px。

**为什么是问题**：聚合器的真实场景大概率是「手机上刷」，而当前移动端既没有优先内容、也不给操作留余量。这不是响应式没写，是**移动端没有独立的信息取舍**。

**修法方向**：390 下把「时间范围 + 排序」收进一个筛选入口（底部 sheet），平台胶囊改「当前平台 + 展开」或两端加渐隐；触控目标统一 36–44px；设置页改为「列表 → 二级页」。

## 2. P1 · 一致性：设计系统在页面层被拆成了三套方言

### P1-1 同一个「分段选择器」有三套实现，行为还各不相同

| 位置 | 实现 | 有滑动指示 | 可访问性 |
| --- | --- | --- | --- |
| Feed 的 `Seg`（时间/排序） | framer-motion `layoutId` 滑块 | ✓ | 裸 `button`，无 `aria-pressed` |
| 平台 `TabRail` | 自绘反色遮罩 `RunMask/GhostMask` | ✓（另一种观感） | 有 `aria-pressed`、有方向键 |
| Item 页「AI 总结 / 原文」 | 自绘 `inline-flex rounded-full` | ✗（硬切） | 有 `aria-pressed` |

同一个控件三种观感、三种键盘行为，用户在页与页之间要重新学。同类问题还有：Toast **三套**（`App.tsx` 3200ms / Settings 3200ms / Market 3600ms）、开关 **两套**（设置页自绘 `h-6 w-11`，无 `role=switch`、无 `aria-checked`）、输入框 **两套**、骨架 **两套**、空态 **三套**、错误态 **三套**。

### P1-2 标题层级没有系统：四页三种 h1，卡片永远 h3

- h1 实测：feed **15px**、settings **19px**、market **19px**、item **26px**。
- 卡片标题 **16px semibold** 比 feed 的 h1 还大——层级倒挂。
- 语义上 feed 是 `h1 → h3 × 30`，**没有 h2**；榜单数字 52px 也不在允许集（11/12/13/15/16/17/19/21/38）内。
- 结果：屏幕阅读器听到「一级标题：全部内容」后直接跳三级标题三十次；视觉上「页面标题」这个概念不存在。

### P1-3 卡片 meta 槽一个位置三种语义

`web/src/components/Card.tsx:189-207`：同一个 43px 高的槽，有时是**摘要**（13px muted），有时是**「点开详情」**（12px fade），有时是**空白**。
更糟的是「点开详情」——它是 CTA 伪装成元信息（`Card.tsx:200`），不携带「为什么给你看」的价值，却占掉一行固定高度。多平台同题时本该显示的「N 个平台同题」也在这个槽里，与 CTA 争位置。

### P1-4 详情页：左边缘跳 136px，正文 55 汉字/行，四种形状挤在一行

- 容器：feed/settings/market 的 `h1Left = 154`；item 页 `h1Left = 290`（1180 容器内再居中 860）。**从列表点进详情，整个内容区右跳 136px**，返回时再跳回来——120ms 的过渡动画放大了错位感。
- 顶部 meta 行四种形状并排：返回胶囊 / 平台实底徽章 / 描边 kind 标签 / 裸文字时长。
- 正文 `text-[14px] leading-[1.9]`、容器 860px → 约 **55 汉字/行**（舒适区 30–40）。
- 统计卡 `min-w-[86px]`，只有「170 评论」一张时右侧留出大片空白（`design/review/item-1440.png`）。
- 链接色写死 `[&_a]:text-[#1E80FF]`（掘金蓝），与平台色体系脱钩。
- 「去 V2EX 看原帖」在**整页最底部**——想离开必须先滚过全部评论。
- 灯箱（代码事实）：`fixed inset-0 bg-black/80` 无 `role=dialog`、无 `aria-modal`、无焦点陷阱、`img alt=""`。

### P1-5 设置页是「开发者控制台」，市场页是「包管理器面板」

- 设置页「运行状态」用 `dl` 两列、值右对齐：`版本 0.3.0.dev0` 与 `条目 639` 横向隔 500px，视线走 Z 字。
- AI 助手每个 provider 一行同时塞 name 输入（31px，显示「Mi」）、key chip（`#047857` 绿色，体系外颜色）、开关、三个 21px 图标；key 输入只有 placeholder「已保存，留空不改」，**没有 label**；「清除所有 key」无 disabled 状态。
- 市场页每张卡：「可更新」实底 +「✓ 已安装」描边 +「更新」实底黑按钮 = **三个强调**；能力 tag 直接暴露 `browser/http/cli`；页脚 12px 直接写 registry URL；空态只有一行灰字。
- 两页都没有「这是什么 / 我为什么要关心」的一句话定位。

### P1-6 暗色语义色缺失

错误态三处都用 `bg-red-50 text-red-700 border-red-200`（feed 错误块、设置 `STATE_TEXT.error`、市场错误块），**无暗色变体**——暗色下会出现一块刺眼的浅红底，与全站变量体系断开。

## 3. P2 · 快改清单

1. 摘要句结尾「…春秋假期？。」——问号后多一个句号（`FeedPage.tsx:117-123` 的数据侧拼接）。
2. 首屏那句「库里共 639 条：主要来自…同一件事最多有 4 个平台在讲：…」是**数据自检报告**，不是给读者的句子。
3. V2EX 卡片摘要直接露出 Markdown 原文「### 前字節開發的中轉」和代码围栏——卡片层没有 strip markdown。
4. 抖音卡片标题与正文是同一句带 `#话题` 的文案，重复渲染两次——平台语义未归一。
5. `TextPanel` 左上角 13px `Quote` 图标在浅底上像一个「99」装饰，不传达信息。
6. 骨架 `min-h-[340px]` vs 真实卡 368.3–444.8px，加载完会跳一下。
7. AI dock：`form` 无 `aria-expanded`、无 `role`、**Esc 不关闭**（实测按 Esc 后焦点仍在 INPUT、面板仍在）、输入框无 label、placeholder 长达一句半。
8. AI dock 写死阴影 `0_10px_30px_rgba(20,20,20,0.12)` 与 `0_18px_50px_rgba(20,20,20,0.14)`，绕过了 `check-ui.mjs` 的正则。
9. `.nav-active` 注释承诺「一条贴着实色的短竖线」，实测 `::before content: none`——**注释在撒谎**。
10. Item 页 `text-[12.5px]`、Card 的 `text-[10px]` 占位、`#6b7280` 写死头像色。
11. 空态文案「这个平台暂时读不到评论。」「Agent 正在看这条内容…（大概十几秒）」——不确定语气 + 无下一步。
12. 市场页 `p-5` 与全站 `p-3/p-4` 不一致；7 张卡两列排，第 4 行单卡孤悬。
13. `index.html` 的 `meta theme-color` 旧报告说「固定白」，实测已随主题动态更新——不算问题。

## 4. 做得好的地方（不要在整改中破坏）

1. **等高契约真的成立**：五档视口每档卡片高度唯一（368.3 / 372.8 / 444.8 / 380.6 / 380.6），一行标题与两行标题的卡片底部对齐——多数同类产品做不到，代价是 `h-[46px]` 固定标题块，可接受。
2. **平台色克制**：品牌色只出现在徽章、面板 6% 底、榜单渐变，没有整卡染色。
3. **暗色是变量切换**，无闪白（`index.html` 首脚本预置 `dark` class），切主题 240ms 过渡。
4. **动效克制且统一**：`EASE [0.22,1,0.36,1]`、四档时长、`prefers-reduced-motion` 全局降级、`button:active scale(.975)` 全局手感。
5. **focus 环基本到位**（纠正旧报告）：Tab 24 站全部有可见环，chip 与卡片是自绘 2px，顶栏与 `Seg` 是 UA 环。
6. **无横向溢出**：五档 `scrollWidth == innerWidth`。

## 5. 根因诊断：不是某个页面没做好，是「设计系统没有兑现机制」

`web/src/theme.css` 有完整的**颜色/阴影** token，但 `web/tailwind.config.js` **没有 `fontSize`、`borderRadius`、`spacing` 的 scale 扩展**——字号只能写任意值 `text-[13px]`，圆角只能 `rounded-xl` / `rounded-card` 混用。于是：

1. 每个页面就近发明组件（Seg ×3、Toast ×3、Switch ×2、输入 ×2、骨架 ×2、空态 ×3、错误 ×3）。
2. 唯一的门禁 `web/scripts/check-ui.mjs`（56 行）只查 4 条：`bg-white`、`text-white`、写死 rgb 阴影、`duration: 0.x`。**不查字号、不查圆角、不查 spacing、不查 focus、不查 aria**，且 `ui-lint-ignore` 可豁免——写死阴影就从正则缝里溜过去了（AiDock 就是例子）。
3. 实测结果：圆角收敛了（9999/12/8/4/6），但字号散成 10/11/12/12.5/13/14/15/16/17/19/21/26/52。

**整改优先级建议**：先补 token scale（字号 5 档 + 圆角 3 档）→ 抽 3 个 primitive（Seg / Toggle / Field）→ 扩门禁到字号/圆角/aria → 再回头修 P0 的视觉。反过来做（先改页面）会让第四套方言长出来。
